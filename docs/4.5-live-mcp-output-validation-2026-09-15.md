# 4.5 live MCP output validation — 2026-09-15

## Scope

The packaged MCP helper now runs a complete Stream Copy tool workflow through
the app's typed IPC endpoint and live FFmpeg adapter. The test generates a
one-second H.264 fixture with the bundled FFmpeg binary, calls `inspect_media`
and `plan_conversion`, submits the plan from another helper process, waits for
the app-owned job to finish, decodes the planned file, and checks `get_job` plus
idempotent resubmission from a reconnected helper process.

The first run exposed an output-path mismatch: the shared adapter passed the
planned filename including `.mov` as `ConversionRequest.outputURL`, but
`FFMPEGConverter` expects a base name and appends the captured extension. The
job reached `succeeded` while the planned `.mov` file did not exist. The adapter
now removes the planned extension before calling the converter and checks that
the planned file exists after live FFmpeg completion. The live test passes with
the exact planned output on disk.

A second live adapter test converts a source with video and audio through
H.264, HEVC, ProRes, Proxy, and Audio Only. Every job returns the exact planned
file, FFmpeg decodes all of its streams, and its stream report identifies the
expected codecs: H.264/AAC, HEVC/AAC, ProRes/24-bit PCM, Proxy HEVC/24-bit PCM,
and Audio Only 24-bit PCM. Together with the packaged Stream Copy case, this
covers the six supported preset IDs on this host.

## Validation

- Focused live packaged-helper test: passed after the fix.
- Focused five-preset live codec/output matrix: passed.
- Full `ApplicationJobContractTests` class: passed, including captured settings,

The tests use an injected unrestricted file-access authorizer for their
temporary fixtures, so they do not replace the first-party folder-grant and
sandbox matrix. FFmpeg decoding is a machine check of the files; representative
playback in the app, channel-routing/timecode cases, and Developer ID packaging
remain release acceptance work.
