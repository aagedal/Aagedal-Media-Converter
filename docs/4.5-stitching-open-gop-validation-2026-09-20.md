# 4.5 open-GOP stitching validation — 2026-09-20

## Finding

Generated open-GOP H.264 exposes a decoded-frame mismatch in the current Stream
Copy stitching path. This is an unresolved correctness issue, beyond the already
reported approximate cut duration. The existing boundary notice does not resolve
it. Do not treat this coverage as acceptance of open-GOP trimmed stitching.

Two new regressions exercise `ConversionManager.convertGroup` and a waiting
shared-service agent conversion, with marker export enabled and disabled. Each
source has two seconds of 24 fps H.264, 12-frame GOPs, two fixed B-frames,
`b-adapt=0:open-gop=1`, no scene-cut keyframes, and stereo 48 kHz AAC. Both retain
the requested 0.5–1.5 second range. Distinct hues and per-channel tones distinguish
the two sources.

The initial diagnostic run found:

- The merged container reports 56 video frames, but 54 frames decode.
- The first 26 decoded frames match the first source's frames 12 through 36,
  followed by frame 39. The last 26 match the same selection from the second
  source. These are the retained frame selections already characterized by
  closed-GOP coverage.
- The two intervening decoded frames do not byte-match any frame independently
  decoded from either original. FFmpeg's `-xerror` decode still exits successfully;
  successful decoding alone does not establish frame integrity.
- Decoded audio contains 114,688 stereo sample frames instead of the requested
  96,000. The no-marker diagnostic output duration was about 2.5414 seconds.

The diagnostic comparison decoded both originals from their beginnings, split
all YUV420P data into 64×48 frame buffers, and searched each output frame against
both originals. It did not decode reference frames using the trimming command
under test.

## Retained regression behavior

The tests require the first and last source-frame selections to remain intact.
The whole-output source-identity assertion is retained inside a strict
`XCTExpectFailure`, one per new case. This records the defect without making
mismatching frame data the expected golden output. Fixing the defect should also
remove these expected failures and revise packet/frame expectations.

Independent assertions still verify bounded output duration and audio length,
stereo identity, tone order, audio energy in every 10 ms window across the
extended join, successful decoding, marker chapters and EDL labels, and agent
queue serialization plus successful separate output. Open-GOP bounds apply only
to these new fixtures; closed-GOP assertions retain their previous bounds.
