# 4.5 live merge coexistence validation — 2026-09-19

## Scope

A regression test runs the real `ConversionManager.convertGroup` concatenation
path and shared agent executor with bundled FFmpeg. Two generated two-second,
24 fps all-intra H.264 clips are each trimmed to one second and merged using
Stream Copy. The first trim subprocess completes before a test barrier pauses
preparation, allowing an agent submission to queue deterministically.

- The agent stays queued while the group owns the shared execution gate.
- Releasing the barrier allows the second trim and merged export to finish.
- Both legacy rows become done and reference the same merged output before the
  agent executor starts.
- The agent then completes its own Stream Copy conversion at its planned path,
  distinct from the group's output.
- Both files contain 48 frames and two seconds of video and fully decode with
  bundled FFmpeg using `-xerror`.

The test uses isolated conversion preferences and synchronized queue bindings.
No production, schema, UI, dependency, or bundled-binary changes are included.

## Validation

- Debug build and all 112 tests across `ApplicationJobContractTests` and
  `ConversionQueueStateTests` passed with zero failures or skips, confirmed from
  the result bundle.
- `git diff --check` passed.
- Evidence: `/private/tmp/amc-4.5-live-merge-suite.log` and
  `/private/tmp/amc-4.5-live-merge-suite.xcresult`.

The sandboxed build could not write compiler/package caches; the approved run
used existing caches. Initial test development exposed Swift isolation errors
and a fixture crash caused by main-actor queue-binding closures. The final
fixture uses synchronized storage, following `ConversionQueueStateTests`, and
passes both the focused run and combined suite. No production crash is claimed.

## Limits

Generated all-intra, video-only sources make trim boundaries deterministic. This
does not validate long-GOP cuts, audio continuity, visual playback, real camera
cards, native bookmarks, encoding-time cancellation, or specialized post-actions.
Named-client workflows, bilingual visual review, and signed Release packaging
remain open release gates.
