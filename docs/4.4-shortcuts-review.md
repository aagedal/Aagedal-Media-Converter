# 4.4 Shortcuts handoff review

## Changes

`PendingAppIntentRequests` now retains cold-launch requests until a notification
receiver actually claims them. Previously, an early `drain()` removed every request
before posting, so a replay before subscriptions attached could lose the request.
Replay snapshots request IDs and checks that each is still pending before posting;
reentrant drains are ignored.

Claiming a buffered request now returns whether that receiver won ownership. All
three App Intent notification handlers decode the payload first and require a
successful claim before changing the queue, preset, output folder, or importer.
Previously, every window in the app's `WindowGroup` could process the same
notification, even after another window consumed its ID. The first receiving window
now owns that submission. This does not promise routing to the frontmost window.
Legacy notifications without request IDs retain their existing behavior.

The notification modifier also drains after yielding from its appearance task,
allowing its subscriptions to attach before cold-launch replay. Any earlier drain
that finds no receiver leaves requests available for this attempt.

## Evidence

`AppIntentHandoffTests` adds regression coverage for repeated replay before a
receiver is ready, three receivers competing for one submission, and replay where
a receiver consumes a later request and attempts a reentrant drain. Ordered replay
now models an actual receiver claiming each request.

On 2026-09-11, a standalone Swift executable compiled the production
`PendingAppIntentRequests.swift` using `xcrun swiftc` and passed assertions for:

- Twenty cold-launch submissions surviving two drains without a receiver.
- Ordered replay exactly once across three simulated window receivers.
- A reentrant drain from the receiving callback.
- A live submission handled once with receivers already attached.
- Legacy notifications without request IDs remaining accepted.

This is an in-process request-buffer check, not a real Shortcuts execution or a
SwiftUI lifecycle test. The integrated release validation records XCTest results.

## Remaining release gate

Run the actual Shortcuts actions with the app quit, open, and with multiple windows;
confirm the selected files appear once in one queue, and immediate conversion uses
the intended preset and output location. Include a no-file action followed by
importer selection and cancellation. Check sandboxed source/output access using a
file outside the app container. None of those live flows were performed in this
review, so the app-open/closed release gate remains pending.

The buffer is process-local and does not provide durable delivery across a crash or
coordinate distinct app processes.

## Follow-up: serialize shared-state handoffs

A second review confirmed that two immediate-conversion notifications could both
claim their requests, then interleave while loading metadata. The second request
could change the shared preset/output before the first called `startConversion`.
The shared `AppIntentOperationQueue` now runs claimed handoffs in FIFO order and
holds the current turn across metadata loading and the full awaited conversion.
Later enqueue/picker notifications also wait before mutating the shared queue or
preset. Request claiming and cold-launch replay remain unchanged.

Immediate conversions reapply their explicit output and preset after metadata
loading, immediately before starting the pipeline. Preset application is
unconditional because the receiving modifier's captured preset may be stale by
the time queued work starts.

Two added XCTest cases suspend an import and then its conversion, verify that a
second job cannot change their preset/output, check a picker arriving during the
conversion waits behind both jobs, and verify new work starts after the FIFO goes
idle. The focused Debug `AppIntentHandoffTests` run passed **13 tests, zero
failures**, including both new methods, on macOS 27.0 (26A428), Xcode 26.6
(17F113). Evidence: `/private/tmp/aagedal-44-handoff-serial-tests.log` and
`/private/tmp/aagedal-44-handoff-serial-tests.xcresult`. The build used the app
scheme, cached packages and `CODE_SIGNING_ALLOWED=NO`; this is not a signed
Shortcuts distribution check. `git diff --check` also passed.

This serializes competing handoffs within the app process; it does not turn the
existing shared queue into isolated per-request jobs. Existing waiting items still
participate in the app's normal conversion behavior. Manual UI changes and other
background queue producers are outside this coordinator. A no-file picker turn
ends when the importer is shown, so overlapping no-file submissions are still
shared asynchronous user interaction, not independent picker jobs. Live Shortcuts
and sandbox permission checks above remain required.
