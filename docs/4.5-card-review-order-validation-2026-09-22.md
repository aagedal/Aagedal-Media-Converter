# 4.5 camera-card review ordering — 2026-09-22

## Changes

The card scanner now keeps each source directory contiguous and sorts clip names
naturally within it. On a two-camera card where both cameras use `C0001.MOV`,
`C0002.MOV`, and so on, global filename sorting interleaved the cameras. The
review only permits a continuation mark for the immediately preceding file, so
it could not represent a two-segment recording from either camera. Directory
ordering makes those adjacent segments markable without inferring that they are
one recording.

The review's import guard now checks each marked multi-file recording's own
compatibility. In “Keep single group” mode, an incompatible whole group no
longer blocks import merely because one internally compatible multi-file
recording is included. An internally incompatible or unprobed multi-file
recording still blocks the reviewed import.

  checks the resulting recordings and day proposal.
- Added a regression for a compatible span inside an incompatible single-group
  proposal, plus the still-blocked unknown-span case.
- All **20 focused grouping tests passed** with isolated DerivedData. Result:

- `git diff --check` passed. An earlier attempt using shared DerivedData was

## Remaining

The temporary tree uses empty `.MOV` files and synthetic timestamps; it does
not validate decoding, MXF metadata, real camera span identity, physical-card
access, export, or playback. Those remain live release checks, along with
screenshots of the English and Norwegian review.
