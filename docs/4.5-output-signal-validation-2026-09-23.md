# 4.5 supported-preset output signal validation — 2026-09-23

The existing live adapter test converted a generated one-second H.264/AAC source
through H.264, HEVC, ProRes, Proxy, and Audio Only. It already verified the exact
planned output path, container extension, bundled FFmpeg decoding, and reported
codecs. This pass strengthened the same test with the app's live media inspector
and decoded audio samples.

For each of the five reencoding presets, the output now must report one 48 kHz
mono audio stream, approximately one second of media, and the expected video
stream count. Video presets must report 24 frames. H.264, HEVC, and ProRes keep
the 64×48 test dimensions; Proxy uses its expected 1440×1080 output dimensions.
The bundled FFmpeg binary decodes each output audio stream to PCM, and a
zero-crossing check verifies the generated 440 Hz tone in the interior half-second.
This catches silent or incorrect audio even when the reported codec is right.

The separate packaged MCP helper test still covers Stream Copy: it inspects,
plans, submits, and decodes the exact planned file through the live adapter.
Both focused tests passed on the macOS host. `git diff --check` passed.

The first run of the strengthened matrix failed only because the new test
expected Proxy to preserve source dimensions; inspection showed the existing
1440×1080 Proxy scaling. The expectation was corrected and the matrix passed.
No converter defect was found in this pass.

These generated, one-second fixtures establish machine-readable probe and
decode checks. They do not establish representative in-app playback, longer or
real-world source behavior, App Sandbox scope behavior, or signed-package
validation. Those remain separate release checks.
