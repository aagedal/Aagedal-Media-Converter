# 4.5 local MCP client setup validation — 2026-09-15

## Scope

Agent Access now offers copyable setup for Claude Desktop, Claude Code, Codex,
and OpenCode. Claude Desktop receives `mcpServers` JSON; Claude Code and Codex
receive commands that register the helper embedded in the installed app;
OpenCode receives a local `mcp` JSON entry with the helper path as one command
array item. All four choices use the actual installed app path. The standalone
[setup guide](../Documentation/LOCAL_AGENT_ACCESS.md) covers access grants,
reconnects, retention, disabling, and the same-session transport policy.

OpenCode's [official local MCP configuration](https://opencode.ai/docs/mcp-servers/)
specifies `type: "local"` and an array-valued `command`; the generated entry
uses that format and adds `enabled: true`.

## Validation

- Debug app and embedded helper build: passed.
- Focused OpenCode configuration XCTest: passed. It parses the generated JSON
  and confirms local transport, a single absolute helper-path command item, and
  the enabled state even when the app path contains spaces.
- Focused bilingual Agent Access UI smoke: passed for English and Norwegian,
  including opt-in, connection test, disabling, and visible options for all four
  clients.
- Claude Code `mcp add` accepted the displayed command form in an isolated
  configuration. Its `mcp list` health check reported the bundled helper as
  connected at user scope.
- Codex `mcp add` accepted the displayed command form in an isolated
  `CODEX_HOME`; `mcp get` reported the correct enabled stdio command path.
- The packaged helper accepted an OpenCode-named MCP `initialize` request at
  protocol `2025-06-18` and returned the six intended tools after
  `notifications/initialized`.
- Norwegian catalog audit: 1,620 entries, 15 intentional untranslated tokens,
  no unclassified omissions or placeholder mismatch.
- `git diff --check`: passed.

The installed OpenCode executable (`/opt/homebrew/bin/opencode`, linked to
version 1.18.30) exited immediately with code 137 for `mcp --help` and
`--version`, including an unsandboxed probe. Its JSON format is validated against
the official documentation and by XCTest, but a live OpenCode connection and
tool call have not been claimed. The earlier popup-picker UI probe could expose
menu choices but did not reliably click them through XCTest; the final UI uses a
segmented picker and the bilingual smoke passes. That smoke checks visibility and
the default Claude Desktop configuration; alternate setup payloads are checked
through the focused test and isolated client registration, not a UI selection
assertion.

## Beta assessment

The client setup surface is ready for wider testing. Beta still requires actual
inspect/plan/submit/follow/cancel calls from Claude Code, Codex, and OpenCode;
packaged cold launch, reconnect, and restart; live denied/lost-access recovery;
six-preset output and playback checks; an explicit App Sandbox scope decision;
and Developer ID signing, notarization, clean-install, and bilingual visual
review. OpenCode runtime verification is now part of the named-client gate.
