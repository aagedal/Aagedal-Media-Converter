# 4.5 manual shared-queue handoff validation — 2026-09-13

## Implemented scope

- Routed ordinary ungrouped manual H.264, HEVC, ProRes, Proxy, Audio Only, and
  Stream Copy conversions through the application-owned planner and serialized
  executor used by local-agent and supported Shortcut jobs.
- Preserved visible manual queue rows by associating each accepted source with
  its exact request and item identity. Fast service updates cannot create a
  duplicate row or claim an unrelated row with the same source path.
- Captured row order, preset and filename settings, date-tag choice, and a shared
  timecode choice before submission. Source and destination grants are persisted
  before the service validates and reopens them.
- Declined the shared handoff before changing ownership when a batch uses merge,
  groups, per-source destinations, unsupported presets, different per-row timing
  choices, custom names, trim, crop, audio routing, mute, waveform generation,
  image sequences, uploads, subtitles, or analytics. Those cases retain their
  established behavior until the application contract represents them.
- Added an info control beside each shared job label. Its selectable popover
  shows the immutable accepted container, codec, quality/rate, metadata,
  subtitle, filename, destination, date/timecode, and capture-time settings.

## Remaining boundary

The shared manual path intentionally covers only semantics present in contract
schema v1. Grouped/merged work and customized per-file conversions can still run
through `ConversionManager` while a shared job is active. Either extend the
contract and executor for the chosen 4.5 matrix or document these paths as not
globally serialized in the first release.

Manual UI validation is still required for row reuse, accepted-settings popover
layout, keyboard and VoiceOver access, real conversion output, cancellation, and
agent/manual concurrency. The new strings and the wider Agent Access pane need a
Norwegian localization and visual review.

Beta still requires two named MCP clients, cold-launch/reconnect/restart and
permission-loss tests, representative output/playback verification for all six
presets, and a Developer ID Release archive with nested-code verification and
notarization.
