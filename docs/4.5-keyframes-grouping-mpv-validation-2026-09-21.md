# 4.5 keyframe markers, recording groups, and MPV ownership — 2026-09-21

## Changes

Stream Copy stitching filmstrips show candidate keyframe ticks when adjacent
candidates are at least eight screen points apart. Dense clusters stay hidden
rather than displaying a sampled subset as though it were complete. A binary
search limits rendering to the visible trimmed source interval. Selected-clip
candidates load even with snapping off (including the initial first-clip preview); whole-group discovery still requires
snapping. Cancelled scans do not poison the session cache. Accessibility exposes
the visible count and a Norwegian-translated label. Three unit regressions cover
trim offsets, viewport edges, density, zoom, and invalid geometry.

Camera-card grouping now has a pure foundation and nine tests. It prefers camera
capture dates over container dates without filesystem-date fallback, uses one
explicit timezone throughout an import, separates contiguous unknown-date runs,
preserves source order, and treats each supplied logical recording as indivisible.
Optional gaps split only when the next start is strictly more than two hours after
the previous recording's end. Missing durations suppress that comparison. Day
boundaries, changing offsets, DST, overlap, exact two-hour gaps, and multisegment
recordings are covered. This is not enabled in the importer: reliable span
identification, compatibility grouping, metadata integration, and preview/options
remain prerequisites.

MPVPlayer no longer retains itself as its C wakeup callback context. A separate
box schedules weak-owner work outside the callback lock; teardown unregisters the
callback and safely handles release from the event queue. MPV flag events now
read the required 32-bit C integer instead of an eight-byte Swift Int. This fixes
independent app bugs, not the still-bundled CoreAudio initialization failure.
See the [dependency investigation and rebuild steps](4.5-mpv-lifetime-and-coreaudio-2026-09-21.md).

## Remaining release work

The bundled MPV dependency requires a tracked CoreAudio fix and rebuilt package;
a passing replay run cannot prove this intermittent failure is fixed. No bundled
binaries, package pins, or licenses were changed here. Broader real-card/MXF/long
recording playback, bilingual visual review, bounded selected-stream ffprobe
scans with source-identity caching, and export-boundary estimates remain open.

Card import still needs span-aware metadata, compatibility splitting, and a
reviewable group preview before enabling date/gap splitting. Named-client MCP
workflows, OS-level grant revocation/lost drives and sandbox scope, Developer ID
signing/notarization, clean install/update, and final release material remain
release gates from the plan.
