# 4.5 ffprobe packaging review — 2026-09-23

## Decision

Keep bounded native keyframe discovery for 4.5. Do not restore a historical
`ffprobe` binary from Git history or resolve to a user's installed copy. Packet
inspection remains an optional follow-up after a distributable, attributed
binary and its release footprint are reviewed.

## Evidence

- The current bundle source has ten helpers and no `ffprobe`.
  `BundledDependencies.json` records 137,003,824 logical bytes for those tools;
  the current FFmpeg 9.0.1 executable is 54,661,504 bytes. The 4.5 plan reports
  that a preserved FFmpeg 9.0.1 build also contains an approximately 52 MB
  `ffprobe`, but that executable is absent from this checkout and local temporary
  build outputs. Its exact bytes, hash, size, signature, and runtime dependencies
  therefore cannot be verified here.
- Git history contains an older 53,294,960-byte `ffprobe` removed in commit
  `ca0788b5`. Running that historical binary reports FFmpeg 8.1 and configure
  flags including `--enable-nonfree` and `--enable-libfdk-aac`. It is not the
  currently attributed FFmpeg 9.0.1 build and must not be restored for a
  redistributable release.
- The Xcode Copy and Sign Media Helpers phase, `scripts/copy-sign-media-helpers.sh`,
  the dependency manifest, and the release bundle audit currently enumerate
  bundled tools explicitly. Adding `ffprobe` requires updating and verifying
  these paths, its matching source and license attribution, signing, and a signed
  Release package. The historical binary alone would increase uncompressed
  helper bytes by 38.9%; the 9.0.1 candidate's compressed distribution impact
  has not been measured.
- `TimelineKeyframeService` already limits AVAssetReader scans to bounded regions,
  caps sample count and elapsed time, handles cancellation, and reports
  unavailable coverage for unsupported sources. No keyframe feature needs an
  unverified executable to preserve its current behavior.

## Reconsideration criteria

Recover the FFmpeg 9.0.1 `ffprobe` from the attributed local build, verify its
configure flags and hash against retained build evidence, then measure its
compressed package impact. If included, wire the signed bundle helper and
manifest, perform a Release bundle audit, and only then implement selected-stream
packet timestamp and flag scans with scoped access and bounded cancellation.
