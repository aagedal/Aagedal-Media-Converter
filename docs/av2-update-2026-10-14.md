# AV2 reference tools update — 2026-10-14

The bundled `avmenc` and `avmdec` now use upstream AVM
`1.0.0-175-g0da4c3647`, revision
`0da4c36474f8d1952bbc54e3ccf833d5f0d2280c` from October 12, 2026:
https://github.com/AOMediaCodec/avm/commit/0da4c36474f8d1952bbc54e3ccf833d5f0d2280c.
This replaces the June 4 build at
`000682c868c9c265fe0bd5b552a8d10ec49ac9a4`. Both tools use the same revision.

The update includes ARM NEON transform and neighbor-update optimizations,
TensorFlow Lite initialization race fixes, and more recent bounds/bitstream
validation fixes. No app encoding defaults, quality ranges, audio routing,
chunking, or container behavior changed. The pipeline remains FFmpeg → Y4M →
AVM, with decoding through AVM → Y4M → FFmpeg.

## Build and signing

```sh
git clone https://github.com/AOMediaCodec/avm.git /tmp/avm
git -C /tmp/avm checkout --detach 0da4c36474f8d1952bbc54e3ccf833d5f0d2280c
bash scripts/build-avm-tools.sh /tmp/avm /tmp/avm/build_arm64
```

The recipe builds static arm64 Release tools, retains TensorFlow Lite, WebM
support and multithreading, and targets macOS 14 (the app requires macOS 15).
No extra runtime libraries were introduced: links remain CoreFoundation,
libSystem and libc++. Compiler identity, flags, local-build and bundled hashes,
and link commands are retained in `provenance/avm-2026-10-12/`.

The checked-in tools have ad-hoc hardened-runtime signatures, verified with
`codesign --verify --strict`. This host has no valid Developer ID identity.
The existing Xcode helper copy/sign phase signs them with the configured build
identity before sealing the app. Developer ID signing and notarization remain
release packaging checks; an ad-hoc signature does not establish notarization.

## Sources and attribution

`build/attribution/avm-2026-10-12-source.tar.gz` retains the entire pinned
upstream tree, including all dependency archives, plus the build recipe,
revision marker, generated version header and standalone rebuild instructions.
Its size/hash are recorded in `AttributionSources.json` and the provenance
directory. As with other source companions, the archive is ignored by Git and
must be retained alongside release source artifacts.

For an offline rebuild, extract that archive and run:

```sh
bash build-avm-tools.sh "$PWD/avm" "$PWD/build_arm64"
```

The recipe restores the supplied version header when Git history is absent.
AVM's CMake build extracts and patches its bundled dependencies locally.
An offline rebuild from the retained archive succeeded and preserved the exact
version string. Its hashes are recorded separately; byte-for-byte binary
reproduction is not claimed.

All 1,744 dependency inputs referenced by the new compiler records exactly
match the retained 4.4 input index, with no added or missing dependency inputs.
Upstream's dependency archives and LICENSE/PATENTS are unchanged. The existing
277 file-level notices therefore remain applicable. `Licenses/avm-LICENSE.txt`
now identifies the new revision and GitHub upstream. The Eigen source companion
was regenerated and reproduced its existing SHA-256 exactly. Explicit gzip
compression level 9 keeps it stable across Python's changed compression default.
Historical 4.4 evidence remains in place; the new build and comparison records
are separate.

## Validation

`scripts/validate-av2-tools.py` creates test media and exercises the actual
bundled command-line tools. It compiles the app's IVF parser/joiner, Matroska
muxer, and AAC parser directly into a small Swift smoke driver.

```sh
python3 scripts/validate-av2-tools.py \
  --tools-dir 'Aagedal Media Converter/Binaries' \
  --baseline-dir /path/to/previous/avm/tools \
  --output-dir /tmp/av2-validation
```

Completed checks include:

- 8-bit and 10-bit CQ and VBR encoding through stdin, with POC progress output.
- Correct decoded dimensions, native bit depth and frame count.
- Byte-identical decoded Y4M for 8/10-bit files made by the previous encoder,
  comparing the old and new decoders.
- Joining two independently encoded chunks, validating timestamps/keyframe
  indices, and decoding the joined IVF and the app-muxed Matroska file.
- The existing `V_AV2`/CodecPrivate probe layout and AAC audio decode in Matroska.
- Lagged IVF output with 12 decoded frames.
- Decoder stdout piped directly to FFmpeg with native 10-bit Y4M.
- The app's XCTest suite: all 1,294 cases passed.
- The dependency manifest check, both AVM source archive hashes, and 32
  dependency/source-manifest regression cases.

The strict release-attribution gate stops at the pre-existing
`swiftmediametadata-3.0.1-source.tar.gz`, which is absent from this worktree.
It needs the other retained source companions restored before release packaging
can be verified. This does not affect the AVM archive checks above.

The final Release build passed, and both packaged helper hashes exactly match
the checked-in tools. Interactive playback, GUI trim/export interaction,
and security-scoped bookmark access were not manually exercised; this change
does not modify those app paths. Generated smoke clips are compatibility checks,
not comprehensive AV2 conformance tests.

## Encoder branch comparison

The separate `av2-enc` candidate at
`b38429d1ea69a3d0e17d4b8ae2495ff0b30b40a0` (October 13) was built and passed
the same initial CQ/VBR, backward decoding and container/audio smoke checks.
On the 12-frame 128×96 test clip, speed 9 and two threads:

- Upstream `main` CQ: approximately 10.0 s (8-bit), 10.7 s (10-bit).
- `av2-enc` CQ: approximately 3.2 s for both depths.
- Previous bundled CQ: approximately 10–12 s.

These small runs were performed during other validation work, without a full
rate-distortion comparison, so they do not predict real-world throughput or
prove equivalent quality. The branch is promising but is not bundled: it does
not yet contain several recent `main` fixes, including the October 12 filter
pointer fix and newer ARM work. The conservative paired `main` update preserves
the latest fixes; evaluating the encoder branch on representative HD/4K footage
and quality metrics is a separate follow-up. Raw candidate results are retained
in the provenance directory.
