# 4.5 OCR-agent coexistence — 2026-09-21

## Scope

Two regressions in `OCRAgentCoexistenceTests` exercise `TesseractService` beside
`ApplicationJobService` using its live FFmpeg adapter. The agent converts a
generated two-second H.264 source through bundled FFmpeg. Each test waits for
actual FFmpeg progress while OCR recognition is outstanding.

The OCR extraction runner supplies a minimal PGS display set to the production
parser. The parser renders a PNG, whose signature is checked by the controlled
recognition engine. `TesseractService` accepts an optional injected OCR engine;
normal callers retain the existing Tesseract/Apple Vision selection.

- Cancelling OCR delivers cancellation to recognition, which deliberately returns
  successful text afterward. The service rejects the late result, publishes no
  SRT, and the agent completes with the expected output duration.
- Cancelling the agent drains its FFmpeg process and records no published output.
  Recognition remains active until explicitly released, then publishes the exact
  expected SRT text/timing as `source.ocr.srt` beside an existing `source.srt`.

Both tests verify unchanged source and existing subtitle bytes, exact output
folder contents, removal of the run's OCR scratch directory, and stable terminal
agent state after recognition finishes.

## Limits

OCR extraction and recognition are controlled test doubles. These tests establish
service cancellation/publication isolation and parsing of the minimal PGS fixture,
not real PGS/VOBSUB demuxing, recognition quality, or Tesseract/Vision termination.
Agent export uses real bundled FFmpeg. Fixture access is unrestricted; live UI,
OS-level security-scoped access, full unit/UI suites, and signed Release packaging
remain outside this increment.
