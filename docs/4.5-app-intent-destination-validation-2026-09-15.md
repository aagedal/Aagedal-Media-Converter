# 4.5 App Intent per-source destination validation — 2026-09-15

## Scope

This continuation moved supported file-bearing App Intent conversions with
“Save next to original” enabled onto the shared application job service. These
requests previously fell back to `ConversionManager` because the first shared
request increment could express only one batch destination.

## Changes validated

- H.264, HEVC, ProRes, Proxy, Audio Only, and Stream Copy App Intent requests now
  resolve and capture an immutable destination for every source when “Save next
  to original” is enabled.
- Custom and preset-suffix subfolders use the same captured filename settings as
  planning, so preference changes after handoff cannot redirect accepted work.
- App Intent date-tag and timecode choices are copied into each per-source
  snapshot as well as the backward-compatible batch snapshot.
- File-access persistence creates and records writable grants only for effective
  output folders. An unused batch fallback is not created or authorized.
- Failed shared submissions build rows against each source's intended output
  folder instead of displaying the unused batch fallback.
- The manual bridge now delegates identical access persistence to the shared
  first-party helper, removing duplicate destination-selection logic.

## Beta assessment

This closes the known per-source-destination fallback for all six supported
file-bearing Shortcut presets. Unsupported presets, groups/merge, generated
waveform behavior, and post-actions still use their established specialized
paths and remain outside the initial shared contract.

This increment does not by itself produce a beta candidate. Live Shortcuts
validation with real security-scoped files is still needed, alongside two named
MCP clients, packaged cold launch/reconnect/restart, denied or lost access, the
six-preset output/playback matrix, the App Sandbox scope decision, and Developer
ID archive/notarization.
