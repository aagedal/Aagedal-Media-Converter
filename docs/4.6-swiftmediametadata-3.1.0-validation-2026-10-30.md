# 4.6 SwiftMediaMetadata 3.1.0 update — 2026-10-30

The app now pins the published SwiftMediaMetadata 3.1.0 release at revision
`b81876ab9fddad0761c50657a05dc56ac0f61f29`. The release exposes Matroska
attachments as `VideoMetadata.attachments`, which the app uses to keep ASS/SSA
subtitle fonts in MKV exports when source metadata is stripped (#64).

## Attribution and retained source

- The project revision, `Package.resolved`, `PackageAttributions.json`, and
  `BundledDependencies.json` all identify the published 3.1.0 revision.
- The source archive is
  `build/attribution/swiftmediametadata-3.1.0-source.tar.gz`: **1,495,633 bytes**,
  SHA-256 `581fd67df186f63c0dd97db92e503c696b7e190afbd1955c86c1fba243aa5aee`.
  It was produced with `git archive --format=tar.gz <revision>`, which
  reproduces the retained 3.0.3 archive byte for byte.
- The uncompressed archive SHA-256 is
  `985d49808e2747a7e713bef62f4a82c56bb2432e384dc59fe6a901fd18881532`.
- The upstream `LICENSE` is unchanged since 3.0.3 and byte-identical to the
  collected SwiftMediaMetadata license notice. No GeoNames data changed; the
  GeoNames acknowledgement now names the 3.1.0 revision.
- `scripts/bundled-dependency-manifest.py --check --require-complete-licenses`
  and `scripts/package-attribution-sources.py --check` pass (90 archives).

## Tests

The SwiftMediaMetadata 3.1.0 release passed its upstream release preflight
(library and CLI tests, archive build) before publication. The app's subtitle
export tests pass against the package resolved from GitHub in a fresh cache.
The app-built H.265/MKV commands were run through the bundled ffmpeg on an MKV
with three font attachments, with metadata stripped and preserved; all fonts
were kept with their filenames and MIME types.
