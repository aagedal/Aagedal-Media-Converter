# 4.5 per-source destination and localization validation — 2026-09-13

## Implemented scope

- Extended the backward-compatible per-source execution snapshot with an
  optional destination folder. Snapshots created before this addition continue
  to decode with the batch destination as their fallback.
- Routed ordinary manual “save next to original” conversions, including preset
  and custom subfolders, through the shared planner and serialized executor for
  H.264, HEVC, ProRes, Proxy, Audio Only, and Stream Copy.
- Planned, authorized, persisted, and revalidated only the unique effective
  destinations used by the sources. A stale or inaccessible unused batch
  fallback folder cannot prevent an otherwise valid per-source request.
- Kept each accepted destination attached to its source through collision
  checks, execution, queue projection, and the immutable settings inspector.
  Batch inspection reports that destinations vary per source instead of showing
  the unused fallback.
- Added Norwegian translations for the Agent Access pane, connection states,
  Manual/Shortcut/Agent origin labels, and the accepted-settings control. The
  localization audit classifies these additions as translated UI.

Per-source Shortcut destinations remain on the established App Intent path. The
first release does not expand an IntentFile grant into independently chosen
output-folder authority.

per-source-destination Shortcut cases still use the legacy executor. Upload,
subtitle-generation, and analytics work also remain outside the shared
application-job contract.

disconnect/reconnect/restart behavior, revoked and unavailable-volume access,
