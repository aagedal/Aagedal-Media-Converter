# 4.5 preview failure recovery — 2026-09-22

## Changes

MPV preview failures now stop the current sequence and show an English/Norwegian
error with Retry. Previously, the controller never observed MPV's error publisher,
and every `END_FILE` event—including failed loads, stops, and replacements—was
reported as successful clip completion. A failed stitching source could therefore
advance the sequence instead of remaining available for inspection and recovery.

Only natural EOF now completes a clip. The EOF property also requires a loaded,
non-failed source. New loads clear the previous MPV error. The preview controller
subscribes to failures using the same lifetime identity as readiness, position,
and EOF, retires the failed player before stopping it, cancels delayed track
refresh, and clears readiness on teardown. Queued callbacks from failed or
replaced players cannot revive playback or advance the sequence. The selected
audio track is retained for retry.

The stitching preview exposes error-panel children to accessibility so Retry is
reachable. The new UI fixture removes its second generated source only after
importing metadata, exercising the real bundled decoder failure path. This is
restricted to Debug UI test sessions.

## Limits

The missing source is generated test media. This does not establish physical
drive removal, native OS grant revocation, real-camera/MXF playback, or recovery
from a decoder that never reports a terminal event. The bundled MPV library and
its licenses are unchanged; the retained CoreAudio initialization-failure patch
still needs the dependency rebuild and validation described in the
[MPV investigation](4.5-mpv-lifetime-and-coreaudio-2026-09-21.md). Developer ID
signing, notarization, and the remaining release matrix stay open.
