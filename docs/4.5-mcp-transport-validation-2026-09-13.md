# 4.5 MCP transport validation — 2026-09-13

## Scope

- Added `Aagedal Media Converter MCP` as a separate Swift command-line target.
  Xcode embeds it at `Contents/Helpers/aagedal-media-converter-mcp`, applies Code
  Sign On Copy, and enables Hardened Runtime without requiring a separate runtime.
- Implemented newline-delimited JSON-RPC over stdio with MCP initialization,
  ping, tool discovery, tool calls, notifications, and structured tool errors.
  Protocol negotiation supports `2025-06-18`, `2025-03-26`, and `2024-11-05`.
- Published bounded schemas for `inspect_media`, `list_presets`,
  `plan_conversion`, `submit_conversion`, `get_job`, and `cancel_job`.
- Added a versioned typed JSON IPC contract over `CFMessagePort`. The app owns
  dispatch and conversion state; the helper never loads app implementation types
  or owns accepted jobs.
- Made the endpoint opt-in and unavailable when disabled. The helper can launch
  its enclosing app without activation and waits for startup before returning a
  stable transport failure.
- Added Agent Access settings for opt-in, connection diagnostics, copyable client
  configuration, helper discovery, file-access guidance, and disabling policy.
- Waited for transport run-loop teardown during shutdown and made restart return
  a failure instead of a false-ready state if an in-flight call prevents draining.

## Transport decision

The provisional 4.5 transport is a bundled stdio MCP helper plus app-owned
`CFMessagePort` IPC. It is runtime-free, local to the user's launch session,
keeps file authorization and execution in the app, and supports reconnecting to
persisted job records. Local agent access remains off until explicitly enabled.

This decision is provisional until two named local MCP clients and a signed
Release package pass the acceptance matrix. `CFMessagePort` does not authenticate
individual same-user processes; enabling the endpoint grants any process in the
same user launch session access to the advertised bounded operations. That trust
model needs explicit release review and documentation.

## Beta assessment

The transport milestone is now functionally proven in a Debug build, so 4.5 is
materially closer to beta. It is not yet a beta candidate: the authoritative
visible queue is still split, supported-client coverage is absent, and the final
Release signing/file-access matrix is unproven. The remaining work is primarily
integration and release validation rather than invention of the MCP workflow.
