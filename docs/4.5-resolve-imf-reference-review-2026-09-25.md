Each package has an `ASSETMAP.xml`, a PKL, a CPL, and three MXF track files.
The ASSETMAP uses `http://www.smpte-ra.org/schemas/429-9/2007/AM`. The PKL
uses `http://www.smpte-ra.org/schemas/2067-2/2016/PKL`; the CPL uses
`http://www.smpte-ra.org/schemas/2067-3/2016`. The CPL has a populated
`EssenceDescriptorList` and each resource's `SourceEncoding` resolves to one
descriptor ID. All three descriptor links and all three MXF track references
resolved within each current package; all five ASSETMAP paths exist. The CPL
and ASSETMAP track-file IDs match the last 16 bytes of the `file_package_umid`
reported by ffprobe for each MXF.

## User-supplied metadata observed

Resolve appended the Composition Playlist, Packing List, Main Video Track, and
two Audio Track text fields to the corresponding filenames. The paths appear in
the ASSETMAP, while the PKL records them as `OriginalFileName` and
`AnnotationText`. The CPL uses `IMF_TEST` for its content title/annotation and
`advertisement` for content kind. It records the timeline start at
`00:00:00:00`; ffprobe reports the same timecode on the MXF track files. The
fractional edit rate and nominal timecode rate are separate fields: `24000 1001`
and `24`, respectively.

The stereo and 5.1 MCA titles entered in Resolve appear in the CPL's
`WAVEPCMDescriptor` soundfield-group subdescriptors, along with language `en`,
content kind `PRM`, element kind `FCMP`, channel labels, and group IDs. The same
title/PRM/FCMP strings are present as UTF-16 in the audio MXF headers. The new
`MCATitleVersion` value also appears in both CPL audio descriptors. ffprobe
reports the audio essence channel counts as 2 and 6. This makes the samples
useful for checking cross-file metadata consistency. It does not establish that
every MCA field is valid or that our exporter can reproduce it.

Resolve was configured to export IMSC1 as a separate file, so it placed a
text-profile `.ttml` sidecar beside each package folder.
Its root declares `ttp:frameRate="24"` and
`ttp:frameRateMultiplier="1000 1001"`. None of the three CPLs has a subtitle
sequence or subtitle track-file reference, and none of the ASSETMAPs includes
the TTML. Thus these exports intentionally provide external sidecars, not a
reference for packaged IMF subtitle track files. Simply moving a sidecar into
the folder would not add the required package and CPL references. The subtitle
text itself was not copied into this review.

The ProRes HDR export was made with Resolve's HDR IMF checkbox enabled without
manually changing the other color tags. Compared with the non-HDR ProRes
package, both the CPL image descriptor and the encoded MXF signal BT.2020
primaries, PQ transfer, and BT.2020 nonconstant-luminance matrix instead of
Rec. 709. The codec remains ProRes HQ and the CPL application identity remains
RDD 45. The HDR descriptor also contains mastering-display metadata. This
shows that the checkbox changed output signaling; metadata inspection alone
does not establish whether Resolve transformed the pixel values from the
source color space or whether the resulting HDR image looks correct.

## Embedded IMSC1 comparison

Resolve also exported `Genereic_IMF_ProResHDR_embeddedSubs`. Unlike the earlier
sidecar exports, this package contains a fourth MXF track file for subtitles.
ffprobe identifies that track as TTML subtitle essence with the same approximate
66.358-second duration as the video. Its CPL has a `SubtitlesSequence` with an
edit rate of `24000 1001` and a `DCTimedTextDescriptor` whose `NamespaceURI`
is `http://www.w3.org/ns/ttml/profile/imsc1/text`. The resource's
`SourceEncoding` resolves to that descriptor; its `TrackFileId` resolves through
the ASSETMAP to the subtitle MXF. The subtitle is also an asset in the PKL.
All four descriptor links and MXF references resolve, all six ASSETMAP paths
exist, and the subtitle MXF's computed SHA-1 matches the base64 values in both
the CPL and PKL. These are structural checks, not a full IMSC or IMF conformance
test. The subtitle MXF reports `01:02:30:00` as its internal timecode while the
CPL and the other MXFs report `00:00:00:00`; this difference needs interpretation
before treating it as an error. The subtitle stream's first packet has PTS 0,
its start time is 0, and its CPL resource has `EntryPoint` 0 and the same
1591-edit-unit duration as the subtitle MXF. The user's subtitle track was
copied from a 50 fps timeline, which may explain the retained internal label;
the files alone do not establish that origin. The observed label does not by
itself indicate shifted subtitle playback.

### Second embedded-subtitle package

`Genereic_IMF_GenericProres_EmbeddedSubs2` is another RDD 45 ProRes HQ HDR
package at `24000/1001` with a CPL-linked IMSC1 subtitle MXF. All four
`SourceEncoding` values resolve to descriptors, all four track-file IDs resolve
to files, and all six ASSETMAP paths exist. Compared with the first embedded
sample, its two audio MXFs are both stereo rather than stereo plus 5.1, and its
CPL uses mostly default metadata (`Untitled`, `feature`, and `n/a` MCA titles).
It mixes filenames with UUID prefixes, UUID suffixes, and descriptive text.
Package readers therefore need the ASSETMAP and track-file IDs instead of
filename patterns. The subtitle MXF again reports internal timecode
`01:02:30:00` while its media start time and CPL entry point are zero. This
repetition is consistent with retained source subtitle metadata but does not
prove its origin or conformance.

## Gap against the disabled exporter

`IMFManifestWriter` currently emits an empty `EssenceDescriptorList`, invents
unlinked resource `SourceEncoding` IDs and track-file UUIDs, supports only one
audio essence, and writes a different CPL and ASSETMAP namespace. Its ProRes
path is called App #5 even though the Resolve sample identifies RDD 45;
SMPTE App #5 denotes ACES. The reference packages supply concrete structures
for correcting these problems, but copying their XML verbatim would not make
new track files conformant. Descriptor values and IDs must come from each
encoded MXF, and the application-specific constraints must be validated.

## 4.5 experimental implementation update

The 4.5 exporter now writes App #2e and RDD 45 packages behind an experimental
label in Preset Settings. It derives CPL track-file IDs, edit rates, and durations
from the wrapped MXFs, links `SourceEncoding` to populated descriptors, and uses
the Resolve sample's CPL and ASSETMAP namespaces. Both presets completed tiny
end-to-end exports in automated tests. The initial scope is one image track and
one PCM audio track; it does not package subtitles or multiple audio tracks.
The five gates above remain the path to delivery conformance. In particular,
external schema/Photon and professional playback QC have not been completed.
