# 4.5 encoding cancellation validation — 2026-09-20

## Scope

Three new `ConversionQueueStateTests` exercise cancellation after the real bundled
FFmpeg has emitted positive encoded-frame progress. They cover a merged legacy
group, a sequential legacy group, and cancellation of an agent job waiting behind
an actively encoding merged group.

The encoder uses normal production command generation and process cancellation.
A test runner adds FFmpeg's real-time input pacing (`-re`) to keep the small media
fixture active long enough for deterministic cancellation. After the real child
terminates with `CancellationError`, the runner suspends its return. This permits
an explicit check that shared execution ownership is retained until cancellation
drainage completes. The tests then release that suspension and verify the next
agent job can execute through the live application FFmpeg executor.

Assertions cover:

- Both merged rows, or the active sequential row, actually reach encoding.
- A shared agent job waits for the legacy group's execution gate.
- Cancelling a waiting agent leaves the legacy encoder running.
- Legacy cancellation reaches the real child through cancellation rather than
  natural completion or timeout.
- Waiting agent execution cannot begin while cancellation drainage is suspended.
- Cancelled legacy rows remain unchanged after late converter completion and
  after the next agent finishes.
- A replacement agent job succeeds after cancellation of the original waiter.
- Source bytes remain unchanged, and the successful agent output has the expected
  duration when inspected with the live media inspector.

No production changes were required for these regressions.
