# 4.5 visible queue validation — 2026-09-13

## Implemented scope

- Added a newest-only async record stream from the actor-owned application job
  service for accepted, progressing, cancelling, and terminal jobs.
- Projected each shared-job source into the existing queue without transferring
  lifecycle ownership to SwiftUI or `ConversionManager`.
- Preserved each accepted output location and displayed the captured preset,
  Agent or Shortcut origin, and a short stable job ID. The complete ID remains
  available to accessibility and in the row tooltip.
- Routed row cancellation to the shared service by job ID. Deleting an active
  shared row requests cancellation and dismisses that projection from the current
  window.
- Excluded service-owned rows from legacy next-item selection, manual bulk
  cancellation, reset, and dock-progress calculation.
- Used the source index as row identity within a job, so repeated occurrences of
  the same input URL remain distinct in a batch.

## Automated validation

Command:

```bash
xcodebuild test -project "Aagedal Media Converter.xcodeproj" \
  -scheme "Aagedal Media Converter" \
  -destination "platform=macOS" \
  -only-testing:"Aagedal Media ConverterTests"
```

Result: **915 passed, 0 failed, 0 skipped** on macOS 27.0 with Xcode 27.0.

New coverage verifies that queue observers receive accepted and cancelled state,
that projected jobs resolve the exact outputs captured by their accepted plan,
and that the legacy queue cannot select, cancel, or include service-owned rows in
its progress calculation.

The result contains five pre-existing Thread Performance Checker QoS
priority-inversion warnings. No new build or test warnings were recorded.

## Remaining boundary

This increment makes agent work visible and cancellable, but does not yet make
the shared service the only conversion owner. Manual queue starts and App Intent
handoffs still use `ConversionManager`, so concurrent work across that boundary
is not yet serialized by one authority. The queue also needs a dedicated view of
the immutable accepted settings rather than relying on the ordinary preset UI.

Manual visual, keyboard, VoiceOver, and English/Norwegian checks are still
required for the new row label and state transitions. Supported-client,
file-access, representative-media, and signed/notarized Release-package matrices
remain release gates.
