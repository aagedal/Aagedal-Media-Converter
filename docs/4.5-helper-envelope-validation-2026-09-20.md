# 4.5 MCP request-envelope validation — 2026-09-20

The stdio helper now distinguishes invalid JSON (`-32700`) from a malformed
JSON-RPC request (`-32600`). It accepts string/integer request IDs, rejects null,
Boolean, fractional, and compound IDs, and rejects non-object MCP parameters
with `-32602` while preserving a valid request ID in the response.

Messages without IDs are handled as notifications: they produce no response and
do not forward request-only tool operations to the app. Previously an ID-less
`tools/call` could invoke an app operation and emit an unsolicited null-ID result.
An ID-bearing call to a notification method receives a method-not-found response.

Seven process-level regressions compile and launch the actual Swift helper. They
cover silent notifications (including an ID-less app-tool call), ID validation,
parse/request error classification, invalid parameters, successful initialization
and six-tool discovery, and continued operation after malformed input. They do
not launch or modify the user's app configuration.

Validation: all 81 Python script tests pass, including the seven new helper tests.
Evidence: `/private/tmp/amc-4.5-sept20-scripts.log`. These checks do not replace
named-client end-to-end testing, signed packaging, or app-owned IPC validation.

Protocol references: [MCP 2025-06-18 base protocol](https://modelcontextprotocol.io/specification/2025-06-18/basic)
and [JSON-RPC 2.0](https://www.jsonrpc.org/specification).
