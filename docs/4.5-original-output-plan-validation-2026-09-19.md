# 4.5 original output plan validation — 2026-09-19

## Scope

Queue output lookup previously selected the first submitted plan linked to a
job in dictionary order. Idempotent retries may have different request IDs and
capture dates while retaining the same conversion payload. Date-based filename
templates can therefore produce different proposed outputs for the same job.

Lookup now requires a plan matching the job's original request. Multiple matching
plans are ordered deterministically by creation time and plan ID. If no original
plan remains in an older snapshot, lookup reconstructs names from the original
request rather than using a retry's capture date. This does not recover names
already discarded by older retention behavior.

No persistence schema, conversion execution, dependencies, or binaries changed.
