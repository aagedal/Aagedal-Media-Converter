# 4.5 patched MPV CoreAudio runtime check — 2026-09-25

The retained 2026-09-22 GPL libmpv candidate still passes
`scripts/verify-mpv-candidate.py`: seven artifact hashes, arm64/x86_64 archive
contents, and patched CoreAudio source correspondence. Its macOS framework
contains a static library, so replacing the dynamic framework inside an app
bundle cannot test it. The app must be relinked against the candidate.

For this local check, an Xcode Debug `build-for-testing` was cleanly relinked
while the candidate temporarily occupied the existing MPVKit Swift package
artifact path. A shell EXIT trap restored the original cached artifact before
testing; its SHA-256 was verified as
`b5ddaaa2fa61ccfbb92bcbcb6e5ddcdb6b4f14316ffde283a8fe23ee1ceba84d`.
The candidate static library's SHA-256 was
`aa7f6fefa346bcce0946c34cb2f1477fcc248e6771d67075c8f793197aacb96c`.
With the same app and test source, the old-artifact Debug dylib hashed to
`dae1676f7c7472276cface2a1af9a9d2b2a568d95c724293027da3407e8240cf`;
the candidate-linked dylib hashed to
`3a27b349d4b9308444091d837b8249595b2726f5e6a32723afefd522636a0e93`.
The app project and its pinned MPVKit package revision were not changed by this
check.

`MPVPreviewObservationTests.testRepeatedCoreAudioPlaybackAndTeardown` creates
a stereo PCM fixture with the bundled FFmpeg, then performs four real libmpv
create/load/play/teardown cycles. Each cycle requires a loaded source, advancing
audio clock, no player error, `current-ao == coreaudio`, and eventual player
release. It skips if the test host has no system audio output. The new case and
all 14 existing `MPVPreviewObservationTests` passed against the relinked app:
15 tests, zero failures. Evidence:
`/private/tmp/amc-mpv-patched-focused-final.log` and `.xcresult`.

The MPV sequence replay UI runner stalled before launching the correctly linked
app or starting a test method. An interactive check then launched that same
candidate-linked Debug app with its generated two-clip MKV stitching fixture.
The first play and two replays each crossed to `ui-test-second.mkv` and stopped
at sequence timecode `00:00:04:00`, with the preview reporting `mpv ready` and
no crash. The app was quit after the check. This verifies replay on the current
host but does not make the automated UI case green.

The direct audio test and interactive replay do not force AudioUnit
initialization failure, a device-change callback, or the original crash
signature. The patched candidate remains unpublished and outside the app's
pinned MPVKit dependency. The release blocker therefore remains open until the
versioned package is integrated and device-change, failure-cleanup, and signed
package checks pass.
