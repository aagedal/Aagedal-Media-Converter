# 4.5 retention queue publication validation — 2026-09-19

## Scope

Creating a conversion plan also cleans up expired plans and terminal job records
past their retention window. That cleanup previously saved the snapshot without
publishing the changed records, leaving existing queue observers with stale rows.

When planning removes retained state, it now uses the existing persistence and
queue-publication helper. Observers receive the authoritative in-memory queue
even if saving fails, while the planning caller still receives the storage error.
Planning that does not remove state keeps its existing save-only behavior.

No wire schema, dependencies, bundled binaries, or execution behavior changed.
