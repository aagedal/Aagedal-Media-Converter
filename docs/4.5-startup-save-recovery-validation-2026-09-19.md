# 4.5 startup save recovery validation — 2026-09-19

## Scope

Startup marked recovery complete before saving the interrupted job records. If
that write failed, existing queue observers did not receive the recovered state,
and subsequent service calls skipped the recovery save.

Recovery now publishes its in-memory results even when saving fails and remembers
that the snapshot still needs to be written. Later requests retry that write
under the existing restoration gate before proceeding. The retry neither reloads
the old snapshot nor repeats interruption, preserving job identity, the original
recovery timestamp, and the diagnostic. No wire schema, dependencies, or bundled
binaries changed.
