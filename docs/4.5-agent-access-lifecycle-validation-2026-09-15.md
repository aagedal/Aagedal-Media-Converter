# 4.5 Agent Access lifecycle validation — 2026-09-15

## Scope

The app-launch restoration task and the Settings opt-in toggle now reconcile the
same endpoint through one actor. Each transition reads the current opt-in value
instead of using a stale launch-time decision. Startup rechecks the value after
the message-port run loop starts (including an unsuccessful startup), so turning
access off during a delayed startup does not leave the endpoint open. Settings
retains the visible ready/disabled states and its packaged-helper connection test.

The regression holds endpoint startup while changing the opt-in state, queues a
disable reconciliation, then releases startup. Neither operation reports an
enabled endpoint, and the final endpoint is stopped.
