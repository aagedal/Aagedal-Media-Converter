# 4.5 OCR stream selection — 2026-09-20

## Scope

A generated mixed-stream MKV exercises the production media inspector and
`TesseractSubtitleStreamExtractor` with bundled FFmpeg. Video and audio occupy
absolute stream indices 0 and 1; two distinct subtitle tracks follow them.
The inspector returns subtitle-relative indices 0 and 1. Extraction uses those
returned indices to select each track and verifies its text, absence of the
other track's text, and unchanged source bytes.

SwiftMediaMetadata 3.0.1 numbers subtitle streams within their stream type in
its Matroska, MP4, AVI, and MPEG readers. The existing `0:s:index` mapping is
therefore preserved. The queue model's misleading “Absolute stream index” comment
is corrected, and the extractor now documents the metadata convention.
No conversion behavior, bundled binary, or dependency changed.

## Validation

All six focused Debug tests passed, including the generated-media regression
(0.336 seconds) and existing extraction deadline/redaction, split progress, timeout
diagnostics, failure diagnostics, and task cancellation tests. The Debug build
and `git diff --check` passed.

- Log: `/private/tmp/amc-4.5-ocr-metadata-selection.log`
- Result: `/private/tmp/amc-4.5-ocr-metadata-selection.xcresult`

The initial sandboxed build could not write compiler/package caches; subsequent
builds used approved Xcode access. An initial absolute-index hypothesis failed
against real metadata, which returned `[0, 1]` instead of `[2, 3]`; the proposed
mapping change was removed before final validation.

## Limits

The fixture uses text subtitles to validate the shared stream-copy extraction
boundary without an OCR model. It does not establish bitmap PGS/VOBSUB decoding,
recognition quality, OCR/agent cancellation coexistence, live UI behavior, or
OS-level security-scoped access. Those release checks remain open. This increment
does not run the full unit/UI suites or validate a signed Release package.
