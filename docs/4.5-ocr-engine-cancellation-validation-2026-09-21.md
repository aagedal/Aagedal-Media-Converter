# 4.5 OCR engine cancellation — 2026-09-21

## Changes

`TesseractOCREngine` now checks task cancellation after its subprocess runner
returns and before interpreting the exit status or recognized text. A result
arriving concurrently with cancellation must not become successful recognition
or an unrelated process-exit error. This matches the existing post-recognition
cancellation check in `VisionOCREngine` and reinforces the service's existing
publication guard.

Three focused regressions cover:

- A runner that returns successful recognition after cancellation.
- A runner that returns a nonzero exit after cancellation.
- Cancellation after a real subprocess reports readiness, through the production
  Tesseract engine and `SubprocessRunner`, with prompt completion after draining.

The first two tests use a controlled completion gate and both failed before the
fix. The third uses a shell/sleep stand-in at the subprocess boundary, preserving
the engine's timeout and exercising real process cancellation without depending
on how quickly Tesseract recognizes a particular bitmap. It passed before the fix.

## Limits

This does not establish cancellation during the bundled Tesseract binary's own
recognition, or during Apple Vision's framework call. The existing real Tesseract
publication/coexistence regression remains separate. Apple Vision's observed
frame timeout, VOBSUB, UI integration, real-world accuracy, OS-level grant behavior,
and signed Release packaging remain open. No bundled dependencies changed.
