# 4.5 recovery link validation — 2026-09-19

## Scope

Recovery previously checked only that a submitted-plan link referenced an
existing plan and job. A malformed snapshot could therefore associate a plan
with an unrelated job, causing submission retries to return the wrong result.

Recovery now requires the original request or an equivalent payload with the
same non-nil requester-scoped idempotency key. This validation runs before the
registry is restored. Invalid snapshots remain untouched and expose no partial
queue state; repairing the snapshot permits recovery on the same service.
No wire schema, dependencies, or bundled binaries changed.
