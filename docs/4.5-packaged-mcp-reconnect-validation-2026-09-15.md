# 4.5 packaged MCP reconnect and access validation — 2026-09-15

## Scope

The embedded Debug MCP helper is now exercised as a separate stdio process
through the app's isolated test message port across multiple client sessions.
The test plans a conversion, revokes source access before submission, verifies
the stable `source_access_denied` tool error, restores access, and submits the
original plan. A new helper session then looks up and cancels the same queued
job. Resubmitting the plan returns the original cancelled job with
`wasAlreadyAccepted = true`, proving that reconnect and retries do not create
duplicate work at the packaged transport boundary.

The existing packaged test still verifies object-shaped preset results and that
an undeclared caller-provided requester ID cannot replace the MCP client's
identity. Both tests use the executable embedded in the test-host app bundle,
not a helper compiled or invoked from the source tree.

## Validation

- Focused Xcode tests: both packaged-helper tests passed on macOS. The new
  reconnect/access test completed in 0.075 seconds.
- `git diff --check`: passed.
- The freshly built Debug app opened with Launch Services via `open -n` and
  displayed the 4.5 Agent Access pane with setup choices for Claude Desktop,
  Claude Code, Codex, and OpenCode. This establishes direct Debug app cold
  launch on this host after the earlier `kLSNoExecutableErr` observation.
- The Agent Access "Test Connection" diagnostic now launches that embedded
  helper as a child process and requires a successful MCP `list_presets` result
  with all six supported presets. The focused English/Norwegian UI smoke passed
  with this end-to-end helper diagnostic in 45.108 seconds.
- A Release app and nested helper build passed. The static Release bundle audit
  verified 45 arm64 Mach-O images with resolved bundled dependencies and 12
  packaged license notices against `BundledDependencies.json`.

The process-level test uses an injected access authorizer and leaves the job
queued without an FFmpeg executor. It proves transport, access rechecking,
reconnect, cancellation, and idempotency, but not a named client's full workflow,
live conversion output, external-drive loss, or Developer ID Release packaging.
Agent Access remained disabled in the manually opened app; a cold-start helper
connection and first-party folder-grant workflow remain beta gates.

An experimental extension of the bilingual Agent Access UI smoke tried to call
the displayed helper from the XCUITest runner after the app reported `Ready` and
its in-app connection diagnostic passed. The helper returned
`transport_unavailable`. A direct runner-side `CFMessagePortCreateRemote` probe
could see neither the UUID test port nor the default port. This is consistent
with XCUITest's app/runner process isolation, but does not establish whether a
normal same-session MCP client can see the endpoint. The experimental UI
assertion was removed. The revised in-app diagnostic does prove a helper child
process can reach the app endpoint, but does not prove an independently launched
client in another process context can. Named-client connection from a normal
login session is therefore still an explicit feasibility gate.
