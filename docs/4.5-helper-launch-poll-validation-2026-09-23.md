# 4.5 MCP helper cold-launch wait continuation — 2026-09-23

The installed build 577 helper hash matches the binary identified in the
[named-client validation record](4.5-named-client-validation-2026-09-23.md).
That Codex CLI call reached the helper and reported a launch timeout, while a
separate `open` command launched the app. The record does not establish whether
Launch Services delivered its completion callback late, the app started slowly,
or the host delayed the helper process.

The helper previously waited up to ten seconds for `NSWorkspace`'s completion
callback before checking for the app's message port. It now polls the port while
the asynchronous launch is pending and keeps the main run loop responsive for
the callback. An available port can serve the request immediately. A reported
launch failure still ends the request, a pending launch has a 30-second bound,
and a completed launch has ten seconds for its endpoint to appear. A completed
launch without an endpoint reports disabled Agent Access as before.

Validation: all seven process-level framing/discovery tests passed against a
freshly compiled helper. The focused packaged helper-to-app XCTest passed,
including `list_presets` and requester identity. `git diff --check` passed.
The new timing path has not yet been exercised by an installed named client;
the app's Agent Access setting was disabled in the prior live run. A successful
named-client cold launch and tool result remain acceptance work.
