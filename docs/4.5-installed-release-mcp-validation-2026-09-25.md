## Cold launch and retention

With the installed app process closed, the installed helper's `list_presets`
call returned all six presets and relaunched the app. A process check confirmed
that the new process came from `/Applications`. After that restart, `get_job`
returned the same job ID, `succeeded` state, and output URL.

The direct helper run validates the packaged stdio-to-app path, one conversion,
cold launch, and durable result lookup. It does not close the named-client
matrix: the current Codex MCP registration still points to the Debug helper,
and Claude Code/OpenCode were not exercised here. Cancellation, access loss,
other presets, playback in the app, and distribution install/update checks also
remain separate release gates.
