# 4.5 preview stress, card ordering, and MPV candidate audit — 2026-09-22

## Changes

Camera-card scanning now breaks duplicate basename ties by naturally sorted full
path, then UTF-8 spelling when natural comparison considers paths equivalent.
This makes queue order independent of filesystem enumeration order while keeping
the existing filename-first behavior. Names do not imply span membership.

Preview regressions exercise 100 native source replacements/dismissals, 100 MPV
observer generations with queued readiness/time/EOF/error callbacks and 200
cancelled tasks, and eight real libmpv missing-source failure/teardown cycles.
Retired sources cannot change the active preview or advance the sequence, and
failed decoder players release. No production preview change was needed.

The new `scripts/verify-mpv-candidate.py` performs a read-only audit of retained
build evidence: artifact hashes, actual universal framework architectures,
XCFramework platform/architecture declarations, and archived framework/static
library correspondence. It rejects missing artifacts, duplicate members, altered
payloads, and evidence paths escaping the candidate directory. Large files are
hashed incrementally and archives are inspected without extraction.

## Remaining

- Card splitting requires reliable format-specific span identity, real-card
  fixtures, and a user-reviewed grouping preview. Existing camera metadata lacks
  the span relationships needed to enable splitting safely.
- Preview stress here does not simulate physical-drive loss, OS grant revocation,
  blocked synchronous decoder calls, or real long-recording playback.
- MPV candidate correspondence does not establish complete dependency/source
  provenance, archive publication, app package integration, CoreAudio failure and
  device-change runtime recovery, or signing/notarization. The app still uses its
  previous MPV dependency.
- Named-client workflows, broader real-media/output/post-action coverage,
  bilingual visual review, clean-install/update checks, and final release
  documentation remain in the release plan.
