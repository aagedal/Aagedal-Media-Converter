### FFmpeg: recorded attribution contradicts binary output

`Binaries/ffmpeg -version` reports `9.0.1`, built with Apple clang
`21.0.0 (clang-2100.1.1.101)`. Configuration includes `--enable-static`,
`--disable-shared`, `--enable-gpl`, and `--enable-version3`. `Binaries/ffmpeg -L`

`Licenses/ffmpeg-LICENSE.txt` begins with “Version 2, June 1991”, and
`scripts/bundled-dependency-manifest.py` hardcodes `GPL-2.0-or-later`.

harfbuzz, freetype, fribidi, x264, x265, vpx, aom, SVT-AV1, vvenc, JPEG XL,

build flags, not exact component revisions or a complete static component list.

it does not identify a preserved source archive or build recipe.

The current replacement is commit
`f49218726200e2da39908333e5a135f87a6ded2f` (“Update MPVKit dependency and bundled
ffmpeg”). Earlier commit `c4fab8cf00664af5d84a18f7db75613793c6b5ee` documents an

historical description does not establish the current 9.0.1 build's contents.

**Required input:** the 9.0.1 source and dependency revisions, patches, build

The same record contains 142 `dep` lines with module versions and checksums.
This makes source retrieval and transitive-notice review substantially more
specific than the `DEV` version alone. Recover it without a Go installation:

```sh
python3 - <<'PYCODE'
```

available when reviewing a replacement. Commit
`4c25f89e22fc86b7c517fe3967044e3fed18514f` calls this a “minimal” build but does
not include the build recipe. Embedded metadata is a useful lead, not an
independently authenticated source-to-binary mapping.

**Required input:** source matching the VCS identity, any custom build selection
