### FFmpeg: recorded attribution contradicts binary output

`Binaries/ffmpeg -version` reports `9.0.1`, built with Apple clang
`21.0.0 (clang-2100.1.1.101)`. Configuration includes `--enable-static`,
`--disable-shared`, `--enable-gpl`, and `--enable-version3`. `Binaries/ffmpeg -L`
explicitly reports GNU GPL version 3 or later. In contrast,
`Licenses/ffmpeg-LICENSE.txt` begins with “Version 2, June 1991”, and
`scripts/bundled-dependency-manifest.py` hardcodes `GPL-2.0-or-later`.

Enabled external integrations reported by the executable include libass,
harfbuzz, freetype, fribidi, x264, x265, vpx, aom, SVT-AV1, vvenc, JPEG XL,
webp, opus, vorbis, mp3lame, theora, openjpeg, vmaf, and whisper. These are
build flags, not exact component revisions or a complete static component list.
The prefix names a temporary `ffmpeg-apple-silicon-9.0.1.tow7Xu` build directory;
it does not identify a preserved source archive or build recipe.

The current replacement is commit
`f49218726200e2da39908333e5a135f87a6ded2f` (“Update MPVKit dependency and bundled
ffmpeg”). Earlier commit `c4fab8cf00664af5d84a18f7db75613793c6b5ee` documents an
8.1.1 rebuild removing non-free components and statically linking Vorbis. That
historical description does not establish the current 9.0.1 build's contents.

**Required input:** the 9.0.1 source and dependency revisions, patches, build
recipe/log, full corresponding notices/material, and reviewed attribution matching
this executable. Correct the manifest and packaged notice together after that
review; do not treat the existing non-null notice as proof of completeness.

### rclone: exact embedded VCS identity is recoverable

`Binaries/rclone version` reports `v1.74.0-DEV`, Go `go1.26.2`, static linking,
and no Go tags. Its embedded Go build information records:

```text
build -buildmode=exe
build -compiler=gc
build -trimpath=true

build vcs=git

build vcs.time=2026-04-27T12:20:42Z
build vcs.modified=false
```

The same record contains 142 `dep` lines with module versions and checksums.
This makes source retrieval and transitive-notice review substantially more
specific than the `DEV` version alone. Recover it without a Go installation:

```sh
python3 - <<'PYCODE'
from pathlib import Path
blob = Path("Aagedal Media Converter/Binaries/rclone").read_bytes()
marker = b"build\tvcs.modified=false"
end = blob.index(marker) + len(marker)
start = blob.rfind(b"path\t", 0, end)
print(blob[start:end].decode("utf-8"))
PYCODE
```

The extraction is intentionally for the reviewed hash; use `go version -m` if
available when reviewing a replacement. Commit
`4c25f89e22fc86b7c517fe3967044e3fed18514f` calls this a “minimal” build but does
not include the build recipe. Embedded metadata is a useful lead, not an
independently authenticated source-to-binary mapping.

**Required input:** source matching the VCS identity, any custom build selection
or patches, and the project's plus 142 modules' applicable notices. Record which
modules/components actually ship after review, rather than assuming a generic
MIT notice for the main project covers everything.

### 96 dylibs: historical Homebrew copying explains the gap

Historical commit `7cfa438` (“Initial libmpv implementation”) contains
`copy_all_homebrew_libs.sh` and `fix_missing_deps.sh`. Inspect with:

```sh
git show 7cfa438:copy_all_homebrew_libs.sh
git show 7cfa438:fix_missing_deps.sh
git ls-tree 7cfa438 mpv-build
```

The first script copies every non-symlink dylib in `/opt/homebrew/lib` that is
not already present, then rewrites install names/dependencies to `@rpath`.
The second copies additional recursive dependencies and also rewrites paths.
Neither captures bottle checksums, formula revisions, build options, notices,
or a source snapshot. `mpv-build` was a gitlink to
`9443097290e82008f26f1597590926c63e7ae053`; it is not evidence that every copied
library came from that build. The latest Frameworks history entry is `6d96428`
(“Removed MPV parts”). Do not rerun the historical scripts to reconstruct the
inventory: they depend on the host's current Homebrew installation.

**Required input:** original bottle/build receipts and source revisions for each
retained image, with evidence accounting for relinking/signing. If unavailable,
a deliberate rebuild from pinned sources with preserved attribution is a clearer
route than guessing from ABI filenames. Removal needs the reachability and
runtime validation already required by the release plan. The manifest lists 96
source dylibs; that is not the number of dylibs in the built app.
