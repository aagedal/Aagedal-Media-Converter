# 4.5 helper cold-launch and input validation — 2026-09-15

## Scope

The packaged MCP helper now asks Launch Services to reuse a running app only
when it is at the helper's own enclosing bundle URL. The default substitution
policy reused the installed stable app when a Debug 4.5 app with the same bundle
identifier was closed. That left the helper waiting for an endpoint the stable
app could not provide. Setting `allowsRunningApplicationSubstitution` to `false`
made a repeat call start the Debug bundle while the installed app stayed open.

The helper also rejects a supplied MCP `arguments` value unless it is a JSON
object. Previously an array, scalar, or `null` became an empty object, so a
malformed `list_presets` call could succeed. The helper now returns JSON-RPC
`-32602` before forwarding such a call to the app. Omitted arguments still
represent an empty object for tools that accept no arguments.

## Validation

- With a UUID-scoped Debug endpoint enabled only through a launch argument, an
  independently launched helper in the normal login session returned all six
  preset records. The saved `localAgentAccessEnabled` preference remained `0`.
- After closing that Debug instance, a helper call with the saved preference
  disabled initially reused the already-running app at `/Applications`; no
  Debug process started. After the substitution fix, the same call started the
  Debug app from the helper's enclosing bundle. It then reported that Agent
  Access was disabled, as expected. The temporary Debug app was closed afterward.
- A focused packaged-helper process regression passed for array-shaped tool
  arguments. All four packaged helper regressions passed after the fix, including
  response validation, requester identity, and reconnect/access.
- The Release build passed. Its static audit verified 45 arm64 Mach-O images,
  Hardened Runtime signatures on every executable, and 12 packaged notices.
  The complete bundled-dependency manifest check and `git diff --check` passed.

This proves separate-process endpoint visibility and exact-bundle cold launch
for a local Debug build on this host. It does not prove an enabled cold-start
tool result through Claude Code, Codex, or OpenCode, or Developer ID Release
signing and notarization. Those remain beta acceptance work.
