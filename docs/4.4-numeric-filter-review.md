# 4.4 numeric filter target review

Reviewed 2026-09-11. Disposition: ambiguous crop targets and numeric filters combined
with app-managed stream mapping changes are rejected before encoding. Full stream
inventory resolution remains outside the supported automatic-adjustment scope.

## Confirmed defect and fix

FFmpeg numeric filter options address output stream order. The existing resolver
correctly declined to guess an output index for whole-input maps, unindexed audio
maps before video, optional preceding streams, graph labels, negative maps, and
absolute input-stream maps. However, crop then treated the unresolved result as
“no existing video filter” and appended `-vf`. This could silently replace a
numeric filter, losing a custom transform. A preceding typed alias could also
be edited despite a later numeric option of unknown ownership.

`PrimaryVideoFilterPlan` now distinguishes ambiguous ownership from absence of a
filter. Active crop returns an empty command and actionable guidance to use
`-filter:v:0` and typed audio filters or explicit required stream maps. The direct
crop helper fails without mutating the supplied arguments. Automatic deinterlace
leaves an ambiguous alias set untouched, preserving the user's explicit filter
expressions when crop is not requested.

A second boundary prohibits numeric filters together with app-managed audio
routing, mute, image-sequence remapping, generated-video pipelines, or additional
output mapping overrides. These transformations can change the output order
after a preset's numeric target has been interpreted. The command fails with an
explanation before conversion starts; typed filters remain the supported path.

## Supported scope and regression evidence

The existing known-order behavior is preserved: automatic mapping assumes the
primary video at output zero; explicit required typed maps count preceding
individual audio/subtitle/data streams; video maps establish the first video
output index; disabled media types do not contribute to output order. Input-side
options do not affect output-side alias resolution. Later matching aliases win.

Regression coverage in `Aagedal_Media_Converter_Tests`:

- `testAmbiguousNumericFiltersRejectCropWithoutMutatingArguments`: six ambiguous
  mapping forms, with both typed and numeric aliases.
- `testAmbiguousNumericFiltersLeaveDeinterlaceAliasesUntouched`: no automatic
  mutation of a potentially overridden alias.
- `testTypedFiltersStillSupportUnknownMapCountsAndIgnoreInputNumericOptions`:
  typed filters remain usable without inventory, with input/output separation.
- `testCustomCropRejectsAmbiguousNumericFilterBeforeEncoding`: full custom preset
  command preparation fails with actionable guidance and no encode arguments.
- `testNumericFilterRejectsMuteBeforeOutputIndexesChange`: a known audio-first
  numeric video target is rejected when mute would shift its index.
- Existing `testNumericVideoFiltersFollowOutputMappingOrder`,
  `testNumericVideoFilterResolutionDoesNotGuessAmbiguousMapCounts`, and
  `testDeinterlaceUsesNumericVideoFilterAfterAudioMap` retain known-map coverage.
- Existing `testGeneratedCropUsesNumericFilterAfterAudioMap` encodes and decodes a
  two-color fixture, checking dimensions and actual cropped pixel values with
  audio mapped before video.

Both new preparation errors use `String(localized:)` and have Norwegian Bokmål
catalog entries. `git diff --check` passed. The parent release-preparation task runs the combined
unit suite; its recorded result is the validation authority for this change.
No live app/manual preview validation was performed for this bounded review.
