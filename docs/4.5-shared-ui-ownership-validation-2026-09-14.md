# 4.5 shared UI ownership validation — 2026-09-14

## Scope

This continuation exercised ordinary manual H.264 work through the live
application-owned job service rather than only through injected executor tests.
It also added bilingual UI coverage for the opt-in Agent Access setup.

The live checks exposed three ownership defects that unit-only validation had not
shown:

- every imported video row carried the enabled waveform preference, so the manual
  bridge rejected ordinary video even though waveform generation was dormant;
- after a manual request was accepted, the toolbar tracked only the legacy
  `ConversionManager`, changed back to Start, and could not cancel the service job;
- the FFmpeg adapter treated `FFMPEGConverter.convert()` returning as completion,
  even though the converter publishes its real outcome later through a callback.

## Changes validated

- Manual representability now checks whether the row actually requires waveform
  video, so ordinary video reaches the shared service while audio waveform work
  remains on the established specialized path.
- The main queue presents legacy-manager and application-service activity as one
  conversion state. Start/reset/clear/merge/auto-encode actions cannot claim work
  during a shared job, and the main Cancel action requests cancellation for each
  active service-owned job.
- Service-owned terminal rows remain authoritative and are excluded from the
  legacy bulk-reset path.
- The live FFmpeg adapter now awaits the converter's completion callback. A real
  successful encode stays running until output validation and post-processing have
  finished; cancellation remains attached to the active job until the subprocess
  drains.
- Agent Access starts and stops its message-port endpoint away from the main
  thread, exposes startup state, disables its diagnostic until startup completes,
  and gives its changing status a stable accessibility representation.
- UI-test launches use isolated persisted-job stores and message-port names so a
  prior launch cannot leak terminal records or endpoint state into another test.
