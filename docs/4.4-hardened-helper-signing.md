# Hardened Runtime helper signing — 2026-09-12

The replacement FFmpeg and rclone source binaries have reproducible ad-hoc
signatures without Hardened Runtime. Previously they were copied as resources,
so the app target's Hardened Runtime setting did not apply to them. Xcode
resource processing could also invalidate existing helper signatures.

All ten source-tree command-line helpers now pass through an Xcode copy/sign
phase after other resources and before the app is sealed. It copies the reviewed
inputs, signs each output with Xcode's expanded identity, enables runtime, and
requests a secure timestamp for certificate signing. Ad-hoc development signing
omits the timestamp. Explicit unsigned builds copy without signing. Declared
input/output paths keep Xcode script sandboxing enabled. Source binaries and
attribution hashes are unchanged.

Release validation now checks valid runtime signatures on every Mach-O
executable, including tools in Resources, before notarization and in the final
ZIP. Developer ID export remains responsible for distribution identities;
this check does not establish notarization success.
