# IMF export conformance disposition — 4.4

Reviewed 2026-09-11. Disposition: **IMF export disabled for 4.4**. IMF import and
saved export preferences are preserved. Re-enabling export requires a separately
validated implementation; a playable MXF or a successful parser round trip is not
conformance evidence.

## Confirmed implementation gaps

`Logic/Conversion/IMFManifestWriter.swift` currently writes:

- An empty `EssenceDescriptorList` while both resources emit newly generated
  `SourceEncoding` UUIDs. Neither resource can resolve its descriptor.
- Newly generated asset/track-file UUIDs without reading the encoded MXF's
  identification metadata or passing those identifiers into the wrappers.
- The composition edit-rate numerator as `TimecodeRate`; fractional 24000/1001
  consequently writes 24000, rather than a nominal timecode frame rate.
- Application selection only in annotation/creator text, with no validated
  application identification or constraints.

There is also a misleading application claim in `IMFModels.swift`: the ProRes
path is labeled App #5 / ST 2067-50. The primary
[Photon project documentation](https://github.com/Netflix/photon) identifies
Application #5 as ACES. Its documentation also identifies AssetMap as ST 429-9
and PKL as ST 429-8, whereas the writer uses purported 2067-8/2016/AM and
2067-2/2016/PKL namespaces. These additional schema/application issues require
investigation before re-enabling; changing the displayed application number alone
would not fix export.

[Netflix's validation guidance](https://partnerhelp.netflixstudios.com/hc/en-us/articles/115002627212-IMF-CPL-ERROR)
explicitly distinguishes XML validation from the open-source Photon checks that
compare CPL descriptors with MXF track-file metadata. No Photon or professional
mastering/QC conformance run was performed during this review.

## Release restriction

`FFMPEGConverter.convert` rejects both built-in IMF presets immediately, before
resolving FFmpeg, probing source streams, allocating package directories, or
starting any helper. This common boundary covers queue and Shortcuts conversions,
including previously saved preset selections. The error explains that descriptors
and conformance are unvalidated and directs users to another preset and a
validated IMF mastering tool. The same explanation appears in IMF preset settings.

The writer and settings remain in source for follow-up work and historical tests;
their presence does not represent an enabled export capability. DCP is outside
this restriction.

## Regression evidence

`ConversionDependencyPreflightTests.testIMFExportRejectsBeforeResolvingToolsProbingOrCreatingOutput`
covers both IMF presets with missing tools and a nonexistent source/output parent.
It asserts one failure completion with the explanation, no tool resolution, no
probe, no progress, no created directory, and no output ownership registration.
The independent helper/audio-preflight tests and IMF settings/command tests remain.
The old converter-level IMF audio-probe and queue-frame-preparation tests were
replaced because the release guard now makes those paths unreachable. Shared
codestream cancellation and wrapper cancellation tests remain applicable to DCP.

Validation status: source review and `git diff --check` completed; the coordinating
release validation run records the executed XCTest results. This review does not
claim that the dormant exporter is conformant.
