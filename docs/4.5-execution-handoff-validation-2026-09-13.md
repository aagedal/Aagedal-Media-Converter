# 4.5 execution-handoff validation — 2026-09-13

## Scope

- Continued milestone 2 after persisted folder authorization.
- Added an injected, transport-neutral executor boundary owned by the shared job
  service rather than a SwiftUI view or client connection.
- Serialized accepted jobs from manual, App Intent, and local-agent origins in
  acceptance order while retaining one authoritative lifecycle record.
- Published executor progress, stages, failures, cancellation, and successful
  output locations through the existing job contract.
- Kept all source and destination security-scoped leases balanced and active for
  the complete executor call.
- Rechecked source identity, destination availability, and output collisions when
  queued work reaches the executor, so waiting cannot silently invalidate a plan.
- Rejected successful executor results whose output locations differ from the
  accepted plan.
- Routed cancellation to the active execution owner, skipped cancelled queued
  work, and waited for executor completion before making active cancellation
  terminal.

## Boundaries still open

The executor protocol is deliberately injectable and is not yet connected to
`FFMPEGConverter`, the visible conversion queue, or App Intent entry points.
Captured application settings still need a concrete execution adapter and
representative generated-media validation. Queue origin labels, the local MCP
transport and six tool adapters, opt-in/setup diagnostics, signed-helper
feasibility, supported-client testing, and the release acceptance matrix remain
subsequent work.
