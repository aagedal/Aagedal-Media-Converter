# 4.5 VOBSUB parser continuation — 2026-09-21

## Findings and changes

Continuing the open DVD bitmap subtitle validation exposed two separate blockers.
The parser treated MPEG-PS pack headers as length-prefixed PES packets, interpreted
control-chain pointers as commands, used the wrong display-date scale, and
misdecoded palette nibbles and variable-length pixel runs. A generated valid DVD
subtitle returned zero frames through the original parser.

The parser now handles MPEG-2 pack headers, reassembles fragmented subtitle PES
payloads, follows forward control links with a terminating self-link, and uses
1024/90000-second display dates. It decodes all four DVD run-code lengths,
end-of-line fills, alternating fields, palette indices, and alpha. PNG output
uses the decoded CGImage directly. Truncated packets, invalid links, pixel offsets,
and runs extending beyond a row are rejected.

The control and run formats were checked against the primary
[FFmpeg DVD subtitle decoder](https://github.com/FFmpeg/FFmpeg/blob/master/libavcodec/dvdsubdec.c).
No bundled dependency or binary changed.

## Validation

The generated fixture includes an MPEG-2 pack header, two PES fragments, separate
start/stop control blocks, four colors, and two interlaced bitmap rows. The expected
start/end times are 2.512 and 3.536 seconds. Tests inspect raw PNG samples to avoid
AppKit display-profile conversion affecting palette assertions.

A standalone run of the original parser returned zero frames for this fixture;
the corrected parser returned one frame and the expected RGB pixel runs. Bundled
FFmpeg independently demuxed and decoded the same `.idx/.sub` fixture to PNGs.
Temporary reference artifacts are in `/private/tmp/amc-vobsub-reference`.

The Debug test-host build and all 17 focused tests passed: four VOBSUB parser,
six OCR, two Whisper, and five subtitle-mux coexistence tests. `git diff --check`
passed. The initial sandboxed Xcode invocation could not write package/compiler
caches; successful runs used approved cache access.

## Remaining extraction blocker

`TesseractService` currently requests stream-copy extraction to `subs.sub` and
expects both `.sub` and `.idx` to appear. The bundled FFmpeg muxer list contains
MicroDVD and DVD program-stream output, but no VOBSUB pair muxer. A `.sub` suffix
alone does not produce the expected bitmap/index pair. This continuation fixes
the parser prerequisite; it does not claim working end-to-end VOBSUB OCR or
VOBSUB/agent cancellation coexistence. Implement a supported extraction path and
then validate selected-track identity, timing, publication, cancellation, and
scratch cleanup through the service.

Apple Vision timeouts, actual recognizer-internal cancellation, real DVD media,
UI integration, OS-level grants, and signed Release packaging remain open.
