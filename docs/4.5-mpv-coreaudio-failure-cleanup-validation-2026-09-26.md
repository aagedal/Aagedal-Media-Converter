# 4.5 MPV CoreAudio failure cleanup — 2026-09-26

The targeted initialization-failure check found a second cleanup defect in the
published `.1` CoreAudio candidate. Normal playback still passes, but the
candidate must not be treated as closing the MPV release blocker.

## Reproduction and fix

`init_audiounit()` already disposes its AudioUnit when initialization or subsequent
property configuration fails. The retained upstream patch added an outer
`uninit()` call without clearing that disposed handle. The outer cleanup then
calls `AudioOutputUnitStop`, `AudioUnitUninitialize`, and
`AudioComponentInstanceDispose` on the stale handle.

The local follow-up
[`mpv-0.41.0-coreaudio-clear-failed-unit.patch`](dependency-patches/mpv-0.41.0-coreaudio-clear-failed-unit.patch)
sets `p->audio_unit = NULL` immediately after the existing failure-path disposal.
This preserves the upstream listener-registration fix and lets the outer cleanup
skip the already-disposed unit. It does not establish that this second defect
caused the originally reported crash.

## Runtime evidence

`scripts/verify-mpv-coreaudio-runtime.py` builds a separate command-line probe
against Xcode's resolved frameworks. It can override only the static libmpv
archive with a local candidate. Its wrappers forward real AudioUnit operations,
force selected failures, track component ownership and exact listener registrations,
and record stale-handle calls without forwarding those invalid calls to CoreAudio.
It neither injects code into the app nor changes system audio settings.

On macOS 27.0 (26A428), the normal login-session audio service was required;
the restricted command sandbox could not initialize an output device. Four
fresh player cycles run in each mode:

| Mode | Published `.1` candidate | Cleanup candidate |
| --- | --- | --- |
| Real silent CoreAudio playback and teardown | Pass | Pass |
| Simulated default-device property callback, continued playback and teardown | Pass | Pass |
| Forced `AudioUnitInitialize` failure | 12 stale-handle cleanup calls | Pass; zero stale-handle calls |
| Forced stream-format property failure | 12 stale-handle cleanup calls | Pass; zero stale-handle calls |

Each final candidate mode creates and disposes four units exactly once and
finishes with zero tracked listeners. Failure modes observe four error endings;
playback modes require an advancing clock and `current-ao == coreaudio`.
The notification mode delivers a callback to the registered listener without
actually replacing or unplugging a device. These checks do not establish physical
hotplug recovery, app UI playback, or signed Release behavior.

The retained [runtime report](dependency-patches/mpv-coreaudio-runtime-2026-09-26.json)
includes both binary hashes and all observations. Logs are under
`/private/tmp/amc-mpv-fault-probe-baseline-final-20260926/` and
`/private/tmp/amc-mpv-fault-probe-cleanup-universal-20260926/`.
