# 4.5 DVD palettes, waveform alignment, and card guidance — 2026-09-21

## Changes

DVD bitmap OCR now requires a complete original 16-color RGB palette. Missing,
partial, malformed, duplicate, or invalid-hex headers produce actionable localized
errors before recognition instead of silently generating invisible frames. The
service distinguishes a missing extracted palette from a missing subtitle stream.
Four new regressions cover both IDX and program-stream entry points, valid
uppercase/whitespace, and service failure preserving the source and existing SRT,
skipping OCR, and removing scratch files. No guessed palette is substituted.

Both native waveform decoding paths now preserve initial audio delay and timestamp
gaps with timestamp-aware resampling. The generated multitrack regression checks
that a stream delayed by 0.5 seconds remains silent at source time 0.1–0.2 seconds,
has its full 10.5-second duration, and retains independent channel amplitudes after
onset. This aligns waveform envelopes with the existing source meters and playback.

Camera-card import now displays a non-blocking performance advisory when an actual
source clip's volume reports removable media. It suggests copying to local storage
while leaving import available. The lookup runs with the existing folder grant,
off the main actor. Unknown volume status and local copies do not show the message;
this is a filesystem flag check, not measured device throughput or card identification.

Completed 35 Norwegian timeline/audio translations left open by recent editor
changes, classified the three numeric meter labels as intentional tokens, and
translated the two palette errors and card advisory. Updated the release plan to
reflect existing split/range edits, undo/redo, waveform/meter support, and keyframe
snapping while keeping the remaining keyframe work explicit.

## MPV blocker found during UI validation

The app process used by the MPV test (PID 57917) crashed at 17:17:46.886 during
second-pass replay. The retained crash report shows `EXC_BAD_ACCESS` in
`mp_msg_va → mp_msg → hotplug_cb`, dispatched from CoreAudio's HAL notification
queue. The log pointer register is zero. Inspection of the local MPV 0.41.0
source finds a raw audio-output pointer passed to this callback; an output
lifetime race is a hypothesis, not a proven root cause. The app uses the
supported `stop` command during teardown, and this inspection did not establish
an app-side misuse responsible for the crash.

Do not treat longer test timeouts as a fix. Investigate and validate callback
lifetime in the bundled MPV dependency, then rerun MPV source switching/replay
and the obstructed range test. No dependency change was made in this increment.
An attempted UI dismissal of the crash notice timed out in Computer Use, so a
clean range rerun was not performed.

A separate code review also found a potential MPVPlayer self-retention cycle
(`passRetained(self)` with release only in `deinit`). It remains to be addressed
and is not established as the crash's cause.
