# 4.4 Swift package notice packaging — 2026-09-12

Baseline: `efd0364`. Development remains 4.4.0 (576).

The offline license viewer and application resources now include Sparkle,
SwiftMediaMetadata, and the upstream acknowledgement for GeoNames data.
Previously the six explicit notice resources did not include these packages.
This closes those concrete notice omissions; it does not claim complete package
or corresponding-source coverage.

## Evidence

Both local package checkouts are clean and match `Package.resolved`:

- Sparkle 2.9.3: `d46d456107feacc80711b21847b82b07bd9fb46e`.
- SwiftMediaMetadata 3.0.0: `c2d77c2dcefcb997623e52beca57bc61ce302cb9`.

The cached Sparkle archive SHA-256 matches the pinned package checksum
`3a5d7fd698acc39c122e75764ed3614b472b284cc483f32ae7006d86c513370c`.
Its `LICENSE` member is byte-identical to the pinned checkout's license and the
new packaged notice. This text includes the project's notice plus bsdiff,
sais-lite, Ed25519, and SUSignatureVerifier notices. The separate retained vendor
Ed25519 license is also preserved as review evidence.

SwiftMediaMetadata's GPL v3 license is copied byte-for-byte. Its selected library
target depends on the system CZlib wrapper and copies `GeoLocationDatabase.bin`.
ArgumentParser belongs to the unselected `swift-exif` executable target, not the
library's dependency graph. The GeoNames acknowledgement is copied from the
pinned README, including attribution, source URL, CC BY 4.0 URL, and the upstream
description of the derived city database. An added preface identifies the pinned
package and that this application packages its database unchanged. This notice
is an acknowledgement, not a copy of the full Creative Commons legal code.

[Evidence snapshots](provenance/4.4-local-builds/swift-package-notices/evidence.json)
record source paths and SHA-256 values, the Sparkle archive identity, and the
GeoNames resource identity. These establish the exact material used; they do not
establish original GeoNames download provenance or audit every source-file header.

## Remaining scope

MPVKit's binary/transitive notices and source mapping remain open. The three
missing AVM/rclone notices remain blocked, as does FFmpeg's explicit
corresponding-source/static-dependency review. The separate
[dylib packaging review](4.4-dylib-packaging-review.md) removes 96 unused source
libraries after establishing they do not ship or serve current helper dependencies. Adding
these resources does not clear or weaken that strict gate. Final source delivery,
signed artifact validation, and full package attribution remain release gates.

Validation results are recorded in the continuation validation document after
building the combined changes. The existing bundle audit checks every manifest
notice byte-for-byte, including all three added resources.

The About and Updates panes also now identify the bundled FFmpeg as 9.0.1
in English and Norwegian; their previous hardcoded 8.1 label was stale.
