# 4.5 stitching playback continuation — 2026-09-20

## Changes

Sequence playback now resolves its starting source through the gapless timeline,
so leading empty clips and a selected clip's out-point advance to the next
playable source. Replaying at the sequence end returns to the first trimmed
in-point. Ordinary pause/resume avoids an unnecessary asynchronous seek.

When SwiftUI delivers seek and playback changes in the same update, a seek now
restores the current playback intent. A backend reload retains the latest source
position. Completion no longer uses a fixed 20 ms early threshold, which could
skip very short clips.

Three unit regressions cover empty sources, out-point mapping, replay after
reordering, and the final subframe. New UI cases generate two trimmed six-second
sources with different in-points, exercise AVPlayer and MPV, and check transitions,
sequence end, replay progress, pause, dismissal, and reopening. The fixture is
confined to the existing DEBUG-only test session and temporary fixture directory.
Accessibility identifiers expose the preview, current source, play state, and
sequence counter without relying on screen coordinates.

## Limits

Generated media does not establish real memory-card/MXF/long-recording playback,
OS-level sandbox grant behavior, reordered/trimmed export content, or seamless
sample-accurate transitions. Native and MPV seeks are asynchronous; the tests do
not exhaust every possible stale-event interleaving during rapid seeks/replay.
Pause during a deliberately delayed source load was subsequently covered by the
[delayed-loading continuation](4.5-stitching-delayed-loading-validation-2026-09-20.md).
