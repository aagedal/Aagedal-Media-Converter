# 4.4 stopped-download recovery review

The previous live-recording stop handler searched the output directory for a
recent video, first by title substring and then by modification time. Two downloads
in one directory could therefore cause a stopped row to adopt—and rename—the
other download's partial file. Live recording statistics used the same heuristic.

Recovery and statistics now use only the latest destination reported by that
row's yt-dlp subprocess. An exact `.part` file takes priority over a completed
filename. Recovery rejects paths outside the chosen directory, symlinks and
nonregular files. It no longer rejects an owned partial simply because a stalled
recording has not changed in five minutes.

For `--live-from-start`, which uses `--no-part`, a directly written destination
must have appeared or changed since its destination report, or have an explicit
`after_move:filepath` completion report. An unchanged older completed file is not
adopted when the user stops before the new partial appears. The recorded comparison
uses inode, file size and modification time.

Seven focused regression tests exercise unrelated recordings, exact partial
selection, old partials, finalized output, unchanged pre-existing output,
`--no-part` growth, and outside-folder/symlink/directory rejection. The existing
post-download details lifecycle regressions are included in the final focused run.
All **9 tests passed** on 2026-09-11 with Xcode 26.6. Result bundle:
`/private/tmp/aagedal-44-transfer-final.xcresult`; log:
`/private/tmp/aagedal-44-transfer-final.log`. The initial sandboxed invocation
could not write Xcode caches; the permitted normal-cache run succeeded.

## Limits

This is recovery of one latest reported output, not reconstruction or merging of
separate partially downloaded audio/video tracks. If yt-dlp emits no usable
destination, stopping fails with the existing partial-file-not-found status and
leaves files untouched. Existing exact `.part` files remain eligible for yt-dlp's
normal resume behavior. Unrelated external writers to the exact same destination
are not coordinated by this change; a changed file signature is local evidence,
not an exclusive filesystem ownership lease. No live network recording was used
for this review.
