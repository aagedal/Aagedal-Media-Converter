# 4.5 runtime access scope — 2026-09-23

## Current distribution target

The 4.5 direct-distribution app target has `ENABLE_APP_SANDBOX = NO` in both
Debug and Release. Neither app entitlements file requests
`com.apple.security.app-sandbox`. The packaged MCP helper is a separate
Hardened Runtime command-line target. This checkout therefore cannot claim
that App Sandbox confines the app or enforces its folder grants. The installed
4.5 build 577 is older than the current checkout and is not a substitute for
checking the final signed artifact.

The local-agent service still requires an approval saved through the app's
bookmark manager for every source and writable destination. It chooses the
narrowest matching grant, resolves symlinks before containment checks, holds
access during validation and execution, and rechecks at submission. These are
application-level access rules for the agent interface; they do not restrict
other app code or a compromised app process. The live native-bookmark test
established approval, persistence, renewal, and symlink containment with local
files, but simulated revocation by deleting a stored approval.

## 4.5 validation target

Validate 4.5 against the **configured unsandboxed direct-distribution target**.
The acceptance matrix should require the app's approval policy to reject
unapproved, removed, and unavailable paths, including a real lost-volume case.
Inspect the final signed app and helper entitlements and test the packaged MCP
workflow under those exact identities. Any future decision to enable App Sandbox
changes the target and requires a separate file-access, IPC, helper-launch, and
conversion regression matrix before release. The present checks cannot be
reported as sandbox-enforcement evidence.
