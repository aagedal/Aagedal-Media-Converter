# 4.5 queued grant validation — 2026-09-19

## Scope

A live shared-job regression extends native bookmark validation from submission
time to execution time. It uses isolated persisted grants, native macOS bookmark
APIs, the shared execution gate, and the bundled FFmpeg Stream Copy adapter.

Three jobs are accepted while the execution gate is held, as it is during
specialized legacy manual work. Before releasing the gate, the test removes the
first job's source-folder grant and the second job's writable destination grant.

- Both affected jobs fail with their respective stable access-denied diagnostic.
- Neither reaches the FFmpeg runner or leaves output/staging files.
- The third, still-authorized job completes at its accepted output path and fully
  decodes with bundled FFmpeg using `-xerror`.
- Renewing the removed grants and recreating the service preserves terminal
  failures: idempotent retries return the original failed jobs without restarting.
- New requests after renewal successfully reuse the failed jobs' output names,
  verifying reservation release and continued queue execution.

No production, schema, UI, dependency, or bundled-binary changes were required.

## Validation

- Debug build and all 107 tests across `ApplicationJobContractTests` and
  `SecurityScopedBookmarkManagerTests` passed, with zero failures or skips,
  confirmed from the result bundle.
- `git diff --check` passed.
- Evidence: `/private/tmp/amc-4.5-queued-grants-verified.log` and

The initial build was blocked by compiler/package cache permissions. The approved
rerun used the existing caches; reading the result summary also required access
to Xcode's report cache.

Persisted approval removal simulates app-level revocation, not OS-level denial.
The held gate models legacy execution ownership; no specialized legacy conversion
runs in this test. Service recreation occurs in-process. Interactive folder
selection, unavailable drives, OS-level revocation, App Sandbox enforcement,
actual overlapping legacy workflows, named-client acceptance, in-app playback,
and signed Release packaging remain separate release gates.
