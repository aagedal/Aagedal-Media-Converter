# 4.5 persisted plan integrity validation — 2026-09-19

## Scope

Recovery validated request payloads and submitted-plan links but trusted saved
source identities and output mappings. A malformed plan could omit a source
identity check or direct execution outside the destination captured in its request.

Recovery now checks source count/order/URLs, output count/order/source mappings,
file URLs, effective per-source output folders, and unique normalized output paths
before committing any records to the registry. Invalid snapshots remain untouched
and expose no partial queue state. Repairing the snapshot allows the same service
to recover and preserve the original job identity and interruption result.

Accepted filenames are preserved rather than regenerated: date templates can
resolve differently after a timezone change. Folder comparisons use normalized
paths so equivalent directory URLs with differing trailing slashes remain valid.
These are structural snapshot checks, not new filesystem grants or a substitute
for the existing submission-time access and source-identity checks.
No wire schema, UI, dependencies, or bundled binaries changed.

## Validation

- Debug build and all 83 `ApplicationJobContractTests` passed; zero failures or
  skipped tests in the final Xcode result bundle.
- Eight malformed-plan variants cover missing, reordered, or unrelated source
  identities; missing or reordered outputs; an unrelated destination; duplicate
  output paths; and a non-file output URL. Each verifies blocked submission,
  no published records, preservation of damaged data, and successful repair.
- A valid unsubmitted plan survives restart with custom names and separate
  per-source destinations, then submits with its accepted output list unchanged.
- The first run caught a trailing-slash directory URL comparison issue in the
