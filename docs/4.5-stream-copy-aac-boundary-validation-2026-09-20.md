# 4.5 Stream Copy and AAC sample-boundary validation — 2026-09-20

## Scope

Two generated-fixture regressions exercise the live shared application job service,
checking the exact planned publication URLs and decoded content as well as metadata.

`testLiveKeyframeAlignedStreamCopyPreservesDecodedSelection` copies a 1–3 second
selection from a four-second H.264/PCM MOV with closed one-second GOPs and no
B-frames. It compares every decoded video pixel and PCM sample against independent
filter trims of the source. The selected output must contain 48 video frames and all 96,000 selected mono
audio samples at the correct offset. Stream Copy can retain the last PCM packet
past the requested end, so less than 1,024 trailing samples are permitted and
the container duration must agree with the actual decoded sample count.

`testLiveAACTrimPreservesSampleAlignmentAcrossPCMAndAACOutputs` trims a 1.25–2.75
second selection from H.264/AAC source media into WAV and H.264/AAC. These boundaries
fall inside AAC packets. A changing-frequency chirp exposes time offsets that
could hide in a constant periodic tone. WAV must reproduce all 72,000 independently
selected decoded source samples within one 16-bit quantization unit (the WAV
export can quantize through 24-bit PCM before comparison). Reencoded AAC must retain all selected
samples with less than one packet of terminal padding. Every 10 ms block is
compared against the source samples with a small lossy-codec error tolerance,
including the start and end of the selection.

## Validation

- `git diff --check`: passed after adding the tests.
- Initial focused execution confirmed 48 exact copied video frames, while the
  copied PCM retained 384 trailing samples (2.008 seconds). Updated the test to
  describe packet-copy behavior instead of incorrectly requiring a sample-exact
  final boundary. The AAC test initially used bit equality across different PCM
  quantization paths; a standalone FFmpeg check established a maximum one-unit
  difference and the assertion now explicitly allows only that quantization.
- The second focused execution passed every decoded-content and duration
  assertion. Codec assertions needed the native MOV inspector's FourCC values
  (`avc1`, `in24`, `mp4a`), rather than only FFmpeg names. The tests now accept
  either representation of the same expected codec, covering native and fallback
  inspection without relaxing media-content checks.
- Final validation: both cases pass in the full 1,027-test Debug unit run,
  with zero failures or skips. Log: `/private/tmp/amc-4.5-sequence-full-unit.log`;
  result: `/private/tmp/amc-4.5-sequence-full-unit.xcresult`.

## Remaining limits

These fixtures use unrestricted test authorization. They do not validate native
sandbox authorization or interactive playback. The Stream Copy case deliberately
uses aligned independently decodable boundaries; unsnapped trims, open GOPs,
B-frame dependencies, and audio packet alignment in copied AAC remain broader
release checks. AAC decoding is checked using the bundled FFmpeg, not every media
player's interpretation of container edit lists or final packet padding.
