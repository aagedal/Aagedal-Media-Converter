# 4.5 publication cancellation validation — 2026-09-19

## Scope

The FFmpeg adapter previously checked cancellation before processing the runner's
completion result. If the converter had already published an output and reported
success, cancellation delivered before the adapter resumed could omit that file
from the cancelled job's completed outputs.

The adapter now validates and retains a successful output before applying
cancellation to the rest of the batch. The job remains cancelled, including when
its final source finished at that boundary, but completed output URLs remain
available in persisted history. A failed runner result does not add an output
merely because a file exists.

The adapter also rechecks cancellation after awaiting its preparation progress
callback, preventing a cancellation delivered during that suspension from
starting the runner.

## Remaining release gates

This validates cancellation around the adapter's authoritative completion
callback, not every converter-specific internal publication stage. Durable
per-file checkpoints before a batch terminates, visual review of mixed-result
rows, named-client workflows, real grant recovery, specialized-job coexistence,
and Developer ID signing/notarization remain open.
