# 4.4 legacy dylib packaging review

Reviewed 2026-09-12. The 96 loose dylibs previously retained under
`Aagedal Media Converter/Frameworks/` were not inputs to the current application
target and were absent from the inspected Release bundle. They have now been
removed from the working tree, eliminating **87,201,936 logical bytes
(83.16 MiB)** of unused checkout content. This is not an application download-size
reduction: the inspected application already excluded these files.

The exact removed paths, sizes and SHA-256 values are preserved in
[`legacy-dylib-removal.json`](provenance/4.4-local-builds/legacy-dylib-removal.json),
together with the independently refreshed Release footprint. Historical binaries
remain in Git history; their removal does not supply missing notices or alter
the licensing of historical distributions.

## Packaging and runtime evidence

The current Xcode project was parsed with `plutil -convert json`, resolving build
file references for application target `8EE6EE952C31FC6B007B629D`:

- Its framework link phase (`8EE6EE932C31FC6B007B629D`) contains only the Swift
  package products `Sparkle`, `SwiftMediaMetadata`, and `MPVKit-GPL`.
- Its resource phase (`8EE6EE942C31FC6B007B629D`) copies ten executable helpers:
  `asdcp-wrap`, `avmdec`, `avmenc`, `bmxparse`, `bmxtranswrap`, `ffmpeg`, `mxf2raw`,
  `raw2bmx`, `rclone`, and `tesseract`. Other resources are notices, assets,
  localization and audio. No source Frameworks directory or dylib is copied.
- Both explicit framework copy phases (`8E1477562ECF959E00C805AA` and
  `608E2E35809FD3AAA29E3747`) have empty file lists. There is no application
  target shell-script phase and no `.dylib` file reference anywhere in the
  project. The synchronized groups are Parakeet and tessdata, not Frameworks.
- `/usr/bin/otool -L` on **all ten current source-tree helper executables** lists
  only `/usr/lib/` and `/System/Library/` dependencies. None links to these loose
  dylibs. These are actual load-command observations, separate from the older
  retained application build.
- Searches across application Swift sources, XCTest/UI-test sources and repository
  scripts found no app or test `dlopen`/`dlsym`, `DYLD_*` override, or runtime lookup
  of the source Frameworks directory. Python bundle-validator tests construct
  their own temporary dylib fixtures. The one obsolete source-directory runtime
  override was in the manifest generator's version probes, now removed.

The retained unsigned Release application at
`/private/tmp/aagedal-continuation-derived/Build/Products/Release/Aagedal Media Converter.app`

It passes architecture, executable-permission and dependency-resolution checks
with **44 arm64 Mach-O images and zero `.dylib` image paths**. Its images comprise
28 MPVKit framework images, five Sparkle images, the app executable, and ten
resource helpers. The earlier checked-in
[`release-footprint-2026-09-06.json`](release-footprint-2026-09-06.json) independently
records the same image layout. Same-component names in package frameworks do not
make them copies of the removed source dylibs. Package artifact identities and
notices require their own review.

This refreshed audit describes a retained build, not a post-removal build. An
attempt to inspect the newer recovery-unit-derived product encountered a missing
app executable while that build directory was being rebuilt; it was not counted
as passing evidence.

## Applied cleanup and next validation

Exactly the 96 tracked regular `.dylib` files recorded in the evidence inventory
were deleted; the directory contained no other entries. The manifest generator no
longer injects `DYLD_LIBRARY_PATH` when probing executable versions. The coordinated
project cleanup also replaces both 603-entry `LIBRARY_SEARCH_PATHS` arrays with
`$(inherited)` and removes the source Frameworks search path. The removed library
paths only repeated the source Frameworks and executable-only Binaries directories.

Local validation after removal: all 15 manifest regression tests pass, and all
eight configured executable version probes succeed without the removed source
directory override.

**Combined validation is pending:** regenerate the manifest alongside the new
notice resources, build Release and run unit/UI checks against the removal, then
re-run final bundle dependency and notice-byte audits. The central release record
will capture those results. No release gate was weakened by this review.

Removing absent, unused files addresses these 96 source-inventory entries without
pretending their notices were recovered. It does not close the AVM/rclone and
FFmpeg source/dependency work or the separate MPVKit package attribution surface.
The final signed/notarized archive and runtime preview/conversion/file-access
checks remain necessary before publishing 4.4.

Final combined validation is now recorded in
[the 2026-09-12 validation record](4.4-validation-packaging-2026-09-12.md):
867 unit tests pass, the post-removal unsigned Release builds and passes its
44-image dependency audit, and all nine notices match. Fresh UI validation was
blocked before test startup by macOS authentication on both attempts; historical
preview results must not be represented as a post-removal UI pass.
