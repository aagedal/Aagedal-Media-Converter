# 4.4 saved-state upgrade review — 2026-09-11

Scope: bounded persistence review against the development 4.4.0 (576) tree,
following `f40ab9f`. This is source/regression evidence, not a completed installed
4.3 → signed 4.4 upgrade test. Tests use isolated UserDefaults suites and injected
bookmark operations; the user's preferences and Keychain are not test fixtures.

## Findings fixed

1. Opening Upload Settings could erase unreadable modern upload-profile data.
   `loadProfiles` returned an empty list after a decode failure, and the editor's
   first-run path immediately saved a new FTP profile over that data. Editors now
   use a throwing read, show a localized recovery explanation, and leave profile
   editing unavailable until the store is repaired. The store also refuses saves
   over unreadable existing data. Regression cases cover damaged JSON, wrong
   storage types, wrong JSON shape, preserved selection, and ordinary missing/empty
   stores accepting new destinations.
2. Saving a bookmark replaced an unsupported top-level bookmark or permission-mode
   store with an empty dictionary, losing recoverable data. Both stores must now
   be absent or dictionaries before a save can publish anything. Regression cases
   preserve both preference domains and balance temporary access after rejection.
3. One malformed bookmark entry prevented every valid sibling from resolving,
   because resolution cast the entire dictionary to `[String: Data]`. Resolution
   now checks only the selected entry. A regression renews a valid stale bookmark
   while preserving a malformed sibling exactly.

## Existing bounded coverage reviewed

- Startup migration preserves the legacy audio preset's format, combines legacy
  visibility, respects explicit modern choices, and runs once. Capture-display
  migration preserves a modern selection and does not resurrect a cleared one.
- Upload migration preserves all four legacy backend configurations and selected
  profile identity, and leaves malformed legacy or modern source data available.
  Credential operations use server/user or access-key associations; the migration
  preserves those fields. Injected SSH-key bookmark tests cover access reloading
  and failed replacement without changing the stored profile.
- Scheduled-download tests cover the absent legacy `audioOnly` field, complete
  round trips, malformed stores and entries, rejected automatic overwrites, and
  explicit recovery. Queue restoration does not partially import damaged data.
- Bookmark tests also cover read/write scope preservation, stale renewal, moved
  URLs, overlapping borrowers, and failed acquisition/renewal.

## Remaining gate

These fixes do not establish the complete release upgrade gate. A controlled
installed 4.3 profile still needs upgrade/restart checks for custom presets,
output/watch destinations, real Keychain access, scheduled downloads, and real
security-scoped bookmarks, including unavailable volumes and permission renewal.
No installer, signed update feed, public release, live credential or actual user
preference store was changed for this review. Arbitrary settings synchronization
and simultaneous cross-process UserDefaults writers are outside this bounded
review; no atomic transaction across different app instances is claimed.
