# 4.7 SwiftMediaMetadata 3.1.3 update — 2026-11-01

The app now pins the published SwiftMediaMetadata 3.1.3 release at revision
`af70dc7af0108c15e991c684e038ce05723c6faf`. It includes 3.1.2 and 3.1.3, which
both fix MXF essence coding labels:

- 3.1.2 recognises SMPTE RP 2008 AVC Long GOP labels (Sony XAVC Long and
  bmx/FFmpeg-written H.264 MXF) as `avc1` with the label's profile, and MPEG-2
  MP@HL / 422P@HL labels (XDCAM HD, HD422) as `mpeg2video`. Before, these
  picture tracks had no codec.
- 3.1.3 decodes labels by SMPTE RP 224 category and codec family instead of
  byte 13 alone. D-10 and DVCPRO HD were reported as PCM, DV25 and JPEG 2000 as
  MPEG-2, and AC-3 / MPEG audio as PCM. ProRes, DNxHD/DNxHR, DV, JPEG 2000,
  FFV1, VC-1 and several audio labels now report ffprobe's codec names.

The codec names the app matches on (`avc1`, `mpeg2video`, `dnxhd`, the ProRes
FourCCs) already map in `FFMPEGCommandBuilder` and `PreviewPlayerController`.
The removed `j2k` / `dv` codec names are not used by the app. With a codec now
present, `CameraCardRecordingMetadata.compatibility` can evaluate XAVC Long and
XDCAM HD card recordings instead of returning `.unknown`.

## Tests

The app's unit tests pass against the package resolved from GitHub at the 3.1.3
revision. The upstream `MXFReaderTests` (91 tests) pass with Xcode's toolchain.
The 3.1.3 `swift-exif` CLI reads an FFmpeg-written H.264 High 4:2:2 MXF as
`avc1` / `High 4:2:2` and a 1080p MPEG-2 4:2:2 MXF as `mpeg2video` / `4:2:2`.
