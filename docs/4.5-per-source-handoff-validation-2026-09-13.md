# 4.5 per-source manual handoff validation — 2026-09-13

## Implemented scope

- Added an optional, backward-compatible per-source settings snapshot to the
  schema-v1 application request. Existing agent, Shortcut, and persisted
  requests without the field retain their original batch-wide behavior.
- Routed ordinary manual rows with individual comments, trim ranges, crop,
  mute, date-tag, and timecode choices through the persisted shared planner and
  serialized FFmpeg executor.
- Validated exact source ordering, source/settings cardinality, finite
  non-negative trim intervals, normalized crop bounds, and nonempty manual
  timecode values before accepting a job. Invalid values return the stable
  `invalid_source_settings` code.
- Applied the captured settings to the exact source/output pair without reading
  current preferences or mutable queue rows after submission. A per-source
  disabled timecode remains disabled instead of inheriting a batch default.
- Updated the queue inspector so each row shows its own comment, trim, crop,
  mute, date-tag, and timecode choices.
- Kept combinations that cannot be represented faithfully on the established
  path. In particular, Stream Copy does not accept crop or mute, and presets
  without visual output do not accept crop.

## Remaining boundary

Per-file audio routing, custom output names, generated waveform behavior,
uploads, subtitle generation, analytics, groups/merge, and per-source output
destinations remain outside the shared contract. These paths can still use the
legacy executor while a shared job is active, so a final 4.5 scope decision must
either serialize them across the boundary or document and test the coexistence
policy.

Manual output validation is still required for each newly shared option,
especially trim/crop combinations, mute, source-preserved and explicit manual
timecode, row inspector layout, cancellation, and concurrent agent/manual work.
The named-client, cold-launch/reconnect/restart, permission-loss, localization,
Developer ID signing, nested-code verification, and notarization gates remain.
