# 4.5 submission visibility validation — 2026-09-19

## Scope

Submission accepted a job and reserved its outputs before saving the snapshot,
but a failed save skipped queue publication. Existing observers could not see
the pending job even though it held an output reservation.

Initial submissions and idempotent retries now use the same persistence and
publication helper as other job transitions. A save failure publishes the
authoritative in-memory record and still reports the storage error. Execution
handoff remains after successful persistence. Users can cancel pending work
while storage is unavailable; later retries save that cancellation without
reviving execution. No wire schema, dependencies, or bundled binaries changed.

## Validation

- The strengthened submission regression failed before the fix with the
  unfulfilled expectation “Unsaved acceptance reaches queue observers.”
- Debug build and all 79 ApplicationJobContractTests passed after the fix.
- `git diff --check` passed.

The regression blocks atomic snapshot writes with a directory at the store
path. It verifies queue publication, a single queued record, and no execution
before recovery. Its four combinations cover original/equivalent-plan retries
and cancellation/no cancellation. Cancellation is now attempted while storage
is still unavailable. After recovery, retries preserve job identity, execute
uncancelled work exactly once, and never execute cancelled work. A fresh service
reload verifies the saved terminal state and output list.
