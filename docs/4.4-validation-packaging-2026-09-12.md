# 4.4 packaging and coordination validation — 2026-09-12

Baseline: `efd0364`; implementation through `dee2d05`.
Host: Apple Silicon, macOS 27.0 (26A428), Xcode 26.6 (17F113).
Development remains **4.4.0 (576)**. No candidate was frozen or publicly released.

## Changes

- `90fab9f`: [Upload coordination](4.4-upload-recovery-review.md) now shares the
  queue's normalized destination identity across cooperating processes. Equivalent
  SFTP/S3 endpoint spellings cannot bypass exclusion; case-distinct S3 object
  names can proceed independently. Existing older development processes must be
  restarted to use the new key format.
- `dee2d05`: [Packaging review](4.4-dylib-packaging-review.md) removed 96 unused
  source dylibs, totaling 87,201,936 bytes (83.16 MiB), and obsolete library search
  paths. None appeared in the app's current link/copy graph or runtime lookups;
  all ten helper executables depend only on Apple system libraries. Historical
  hashes and the supporting bundle graph remain recorded. This does not reduce
  the already-built app by 83 MiB: the files were excluded from it already.
- `dee2d05`: [Swift package notices](4.4-swift-package-notices-review.md) adds
  Sparkle, SwiftMediaMetadata, and GeoNames notices to resources and the offline
  viewer. Sparkle's archive hash matches the pin and its notice matches both the
  source checkout and archive. The packaged GeoNames database matches the pinned
  source resource hash. About and Updates identify FFmpeg 9.0.1 in both languages.
- `2cacb4a`: AVM evidence indexes 1,744 compiler inputs and verifies 39 snapshots,
  17 component fingerprints, and optionally 858 retained dependency records.
- `5e43caa`: rclone's source-selection audit matches 922 packages and all 142
  dependency module version/checksum pairs to the executable. All 66 selected
  embedded asset byte sequences occur in the binary. Retained file-level notices
  include material missed by filename-only notice recovery.

## UI validation blocked by host authentication

Both attempts failed before any UI tests ran. XCTest reports:
`LocalAuthentication Code=-4: System authentication is running` and
`Authentication canceled`. The second attempt reused the built executable with
`test-without-building`. This is an environment failure, not a passing UI run or
an observed application assertion failure. The user was asked to finish or dismiss
any active system authentication prompt. The prior 19 passing workflow tests are
historical evidence only; a fresh post-cleanup run remains required.

The first sandboxed Release invocation also lacked Xcode cache permissions; the
successful invocation used approved access. No production workaround was added.
