The first focused MPV sequence replay UI run used `CODE_SIGNING_ALLOWED=NO`.
It stopped making progress before starting any test method and was interrupted.
The resulting app had only an ad hoc linker signature; macOS app assessment did
not accept it. The user has sometimes seen a macOS dialog saying the test app
was invalid and should be deleted. The dialog text was not captured, so the
unsigned bundle is a plausible cause rather than a confirmed diagnosis.

A fresh Debug UI test build with normal Apple Development signing passed
`codesign --verify --deep --strict`. Its
`testMPVStitchingSequencePlaybackAndReplay` UI test then ran and passed in
82 seconds. All 15 `MPVPreviewObservationTests` also passed again with the
signed build, including repeated CoreAudio playback and teardown. Logs and
result bundles are at `/private/tmp/amc-45-coreaudio-signed-ui.log`,
`/private/tmp/amc-45-coreaudio-signed-ui.xcresult`,
`/private/tmp/amc-45-coreaudio-signed-mpv-tests.log`, and
`/private/tmp/amc-45-coreaudio-signed-mpv-tests.xcresult`. Future interactive
UI test runs should use the project's normal signing configuration.

This validates the published package, signed Debug UI playback, and unsigned
Release archive. The original failure signature still needs a targeted
AudioUnit initialization failure and hotplug/device-change exercise on an
affected macOS system. A signed Release bundle and the full release process
also remain to be checked before marking the MPV crash blocker closed.
