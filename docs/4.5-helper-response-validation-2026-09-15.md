# 4.5 packaged helper response validation — 2026-09-15

## Scope

The MCP helper now checks the app's versioned IPC response before presenting a
tool result. The response must match the sent request ID, use schema version 1,
and contain exactly one of `result` or `failure`. A newer response schema or an
ambiguous success/failure payload returns the stable `transport_unavailable`
tool error with an invalid-response explanation. The helper does not replay the
tool call after this error.

A focused regression launches the helper embedded in the test-host app as a
separate stdio process and uses a temporary message-port server to return both
malformed response types. The existing packaged helper requester-identity and
reconnect/access tests also pass with the stricter validation.
