# 4.5 upload-agent coexistence — 2026-09-20

## Scope

Two regressions in `UploadLifecycleTests` exercise the production `UploadManager`
and `ApplicationJobService` with its live FFmpeg adapter. Each generates a
two-second H.264 fixture, starts an upload through a controlled `RcloneUploading`
service, and waits for actual progress from the bundled FFmpeg agent export.
The FFmpeg runner paces input so cancellation occurs while the export is active.

- `testUploadCancellationPreservesRunningAgentExport` cancels the upload, delivers
  late progress and successful completion from its service, and verifies the row
  remains cancelled without a remote path or stale progress. The agent subprocess
  stays active and completes successfully with the expected output duration.
- `testAgentCancellationPreservesRunningUpload` cancels the shared agent job,
  verifies its subprocess drains and no output is published, and checks the upload
  remains active with its operation identity. The upload then completes successfully
  without receiving cancellation, while the agent record remains cancelled.

Both tests verify unchanged source/upload-file bytes, cleared terminal upload
operation identity, stable final job state/output URLs, and exact directory
contents with no staging or partial files. No production changes were needed.

## Limits

The upload service is a controlled test double that deliberately returns success
after cancellation. This validates manager ownership and late-callback handling
alongside a real agent media subprocess; it does not establish live rclone process,
network, remote publication, credentials, or upload UI behavior. File authorization
is unrestricted for the generated local fixtures. Inference/OCR, real security-scoped
access, manual playback, and signed packaging remain open. The full unit and UI
suites were not run for this test-only increment.
