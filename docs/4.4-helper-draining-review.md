# 4.4 helper draining review

Reviewed 2026-09-11. This review covers updater cancellation and retry ownership;
package/framework attribution remains a separate release gate documented in
`4.4-dependency-provenance-review.md`.

## Confirmed defects and changes

- Deno Settings cancellation discarded extraction/update task handles before their
  work finished. A retry could start while a cancelled extractor or installer was
  still draining. Cancelled owners now remain retained until completion.
- Deno update replacement cleared its owner and suspended before registering the
  replacement. Reentrant requests could bypass that wait. Replacement tasks now
  become the owner before suspension and await their predecessor inside the task.
  Cancelled queued replacements preserve the entire predecessor chain.
- Direct Deno extraction replacement cancelled the old helper without awaiting it.
  It now uses the same drain chain, checks cancellation before starting extraction,
  and retains existing generation checks and scratch-directory cleanup.
- yt-dlp Settings cancellation previously reached only the URLSession download.
  Release lookup and checksum verification could continue and install afterward.
  A whole-update owner now propagates cancellation through every async phase,
  serializes replacements, and checks cancellation before publication.
- URL download completion cleared its per-kind task slot unconditionally. Cleanup
  now checks task identity so an old completion cannot erase a newer task handle.

## Regression coverage

`DenoExtractionDrainTests` adds three cases: explicit Settings cancellation followed
by retry; cancelling a queued replacement then replacing it again; and an already
cancelled caller preserving the active extraction. The injected runner observes
cancellation but deliberately delays completion and performs a final scratch-file
write. These tests verify that replacement helpers do not start before that drain.

`YTDLPUpdateOwnershipTests` exercises Settings cancellation while post-download work
is suspended, with no URLSession task registered. A cancelled intermediate retry
must drain the first operation before the final replacement begins, and cancelled
operations must report cancellation even if their underlying work returns success.

The parent release-preparation task runs these tests with the aggregate Xcode unit
suite; consult its validation record for the actual result. Existing extractor and
installer tests additionally cover scratch cleanup, checksum cancellation, atomic
Deno replacement, and preservation of the installed runtime when cancelled before
publication.

## Limits

These are deterministic in-process ownership tests, not a manual download/install
exercise with GitHub or a cross-process installation lock. Once an atomic binary
publication has occurred, cancellation does not roll it back. yt-dlp binary/version
publication remains a sequential filesystem operation rather than a transaction.
Framework reachability, binary archive provenance, complete attribution, and final
signed Release bundle validation are not established by these tests.
