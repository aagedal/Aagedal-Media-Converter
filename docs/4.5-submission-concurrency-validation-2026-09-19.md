# 4.5 submission concurrency validation — 2026-09-19

## Scope

The shared service now holds a per-service admission gate through submission
validation, registry acceptance, output reservation, persistence, and execution
enqueueing. Although the service is an actor, calls to its separate registry
actor suspend it. Previously competing submissions could pass the reservation
check before either resumed from registry acceptance to reserve the output.
Concurrent same-plan retries could also pass the initial submitted-plan lookup.

The gate is released on both success and failure. It is independent of the
conversion execution gate: submitting new work does not wait for an active
conversion to finish. The wire contract, persistence schema, and supported
presets are unchanged.
