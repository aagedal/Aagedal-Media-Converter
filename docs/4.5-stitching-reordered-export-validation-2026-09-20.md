# 4.5 reordered stitching export validation — 2026-09-20

## Scope

The new `testLiveReorderedTrimmedStitchPreservesFramesChaptersAndNotes` runs
the real `ConversionManager.convertGroup` Stream Copy path with marker export
enabled and the bundled FFmpeg. Two generated two-second, 24 fps, all-intra
H.264 MOV sources have distinct colors and changing frame content.

The test reverses their queue order and applies asymmetric trims: source two
retains frames 18–35, then source one retains frames 6–35. The resulting MOV
contains exactly 48 frames. Decoding the entire output to raw YUV produces
byte-identical data to those independently selected source frame ranges in
that order. Both queue rows finish successfully and refer to the same output.

Source-relative notes survive the reorder and trims. Embedded chapter titles
and ranges are checked at 0, 0.25, 0.75, and 1.25 seconds, ending at two seconds.
The actual output's `.cuts.edl` sidecar contains matching titles at frames
0, 6, 18, and 30. Notes before the in-point and exactly at the excluded out-point
appear in neither chapters nor the sidecar.

## Limits

This verifies the real export boundary using the reordered and trimmed items
that the editor supplies. It does not automate gestures followed by export in
the editor, validate real camera-card/MXF/long recordings, or establish exact
long-GOP or compressed-audio cut behavior. Existing source-chapter Keep/Replace
prompts, OS-level bookmark revocation, named-client workflows, bilingual visual
review, and signed Release packaging remain separate validation work.

No production code, dependencies, or bundled binaries changed; this continuation
does not claim a new Release package or signing/notarization result.
