# 4.5 bounded keyframe discovery and cut feedback — 2026-09-21

## Changes

Stitching keyframe discovery now reads compressed video samples only near trim
endpoints and the selected playhead. Initial searches cover roughly 30 seconds;
missing neighbors expand the search up to 120 seconds. Five-second region
quantization allows reuse, and the service retains at most 32 completed scans.
A sample-count limit and eight-second reader watchdog bound the sample-reading
phase; metadata loading and reader initialization are not covered by that deadline.
Cancellation reaches the active AVAssetReader, and scoped source access remains
held until reading finishes.

Cache keys include fresh file resource identity, size, modification time, video
track ordinal, and requested region. Foundation URL resource caches are cleared
before reading identity: the first regression run demonstrated that otherwise an
atomic same-path replacement returned stale attributes. Files changed during
inspection do not publish results. Only completed regions supply markers and
snapping; incomplete reads do not imply coverage. AVAssetReader ranges exclude
their upper endpoint, and published coverage preserves that distinction.
Adjacent completed regions merge. Snapping falls back to frame boundaries when
an unscanned neighboring region could contain a closer candidate.

Free Stream Copy trimming displays the requested start, the preceding known seek
candidate, and its time difference. A candidate is shown only when continuous
scanned coverage reaches the requested cut. The panel explicitly says the export
can differ. This is a start seek estimate, not an exact decoded in/out boundary
or a short export preview. English and Norwegian strings are included.

The range-selection UI regression used XCUICoordinate's touch-oriented
`press(forDuration:thenDragTo:)` API. macOS mouse drags require
`click(forDuration:thenDragTo:)`. The corrected tests target an explicit range
surface and verify forward/reverse selection, clearing, deletion, undo, and redo.
The ruler test now proves the drag changed clips, rather than relying on a prior
click that had already selected its destination. An experimental native range
surface did not resolve the touch-event issue and was reverted; the original
SwiftUI gesture remains.

## Remaining scope

The current app bundle does not contain ffprobe. No binary, package pin, or license
changed. Discovery therefore remains AVFoundation-based and uses the first video
track used by native preview; the service supports explicit video-track ordinals.
Unsupported containers remain unavailable. Packet-level selected-stream ffprobe
inspection and source-start normalization need a deliberate packaging/implementation
decision. AVFoundation timestamps already follow the asset timeline; subtracting a
delayed track's start would move candidates away from preview time.

Real-card/MXF/long-recording stress, actual Stream Copy boundary previews and
out-point estimates, bilingual visual review, span-aware card grouping integration,
the MPV CoreAudio dependency rebuild, named-client MCP workflows, OS-level grants
and lost drives, sandbox scope, signed/notarized Release packaging, clean installs
and updates, and final release materials remain open.
