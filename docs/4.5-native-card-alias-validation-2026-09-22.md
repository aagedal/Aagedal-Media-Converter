# 4.5 native preview, card metadata, and output aliases — 2026-09-22

## Changes

Native AVPlayer source loading now has a 30-second deadline while its status is
unknown. Expiry retires native observers/player state before invoking the existing
MPV fallback and preserves selected audio. Native readiness, replacement, and
teardown cancel the deadline; stale tasks cannot retire a replacement. Existing
native metadata/initial-seek deadlines and MPV failure/Retry behavior remain.

`CameraCardRecordingMetadata` adapts explicitly resolved logical recordings into
the recording-day grouping foundation. It takes dates only from the first
segment (camera metadata preferred over container metadata), requires every
segment duration for end-to-start gap estimates, and conservatively checks all
video/audio streams before proposing compatibility. Missing multichannel layouts
require review. The scanner is not connected to automatic splitting: reliable
span identification, reviewed import options, and real-card fixtures remain open.

Shared-job planning and submission resolve symlinked ancestor directories for
internal output identity. Competing aliased destinations cannot reserve the same
output, per-source duplicates are rechecked at submission, and cancellation
releases the captured reservation. Accepted public paths are unchanged; resolution
occurs while existing destination access leases are held. Direct destination
symlinks retain the existing destination-validation policy.

## Limits

Controlled deadline tests establish asynchronous timeout and callback retirement,
not recovery from a blocked main actor or synchronous decoder hang. This run does
not establish real external-drive removal, OS-level permission revocation, or
long-recording/card behavior. Output identity handling does not claim to solve
case-folding, hard-link aliases, or directory retargeting after job admission.

The separate [isolated MPV rebuild](dependency-patches/README.md) produced patched
arm64/x86_64 candidates. This app still uses the existing MPVKit dependency, so
preview checks against this app cannot close the CoreAudio dependency blocker.
Named-client workflows, signed Release/notarization, clean-install/update checks,
and the remaining real-media/output matrix are still release gates.
