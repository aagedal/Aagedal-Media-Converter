# 4.5 MCP helper transport continuation — 2026-09-15

## Scope

The helper now retries only while the app's message-port endpoint has not
appeared during startup. After a port exists, a failed send or malformed reply
returns one transport error to the MCP client. This avoids replaying a tool call
that may already have reached the app, especially after the five-minute reply
timeout. `plan_conversion` always uses the helper's sanitized MCP client name as
its requester ID; an undeclared `requester_id` argument cannot override it.

The synchronous stdio loop runs on the main thread. Its cold-launch wait now
pumps the run loop so `NSWorkspace` can deliver a main-thread completion handler,
and a locked result removes the concurrent closure mutation warning.

The supported [MCP 2025-06-18 tool-result schema](https://modelcontextprotocol.io/specification/2025-06-18/schema#calltoolresult)
requires `structuredContent` to be an object. `list_presets` returns a list from
the app, so the helper now exposes `{ "presets": [...] }` in both structured and
text content. Other tools continue exposing their object results directly. The
Debug helper shares the app's UUID-scoped test-port override for an isolated
packaged stdio-to-app round trip.
